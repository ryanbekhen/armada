# CLAUDE.md

Guidance for Claude Code when working in this repository.

## About the project

Armada is a multi-machine container platform (cloud instances, VMs, or bare metal; do not describe it as VPS-specific). Docs describe Armada on its own terms: do not compare it with or name other products unless a component or protocol really needs naming. Two binaries, written in Rust (ADR 0027, ADR 0055): `armadad` runs on every machine as root, as `armadad server` (control plane) and `armadad agent` (runs containers on the supervisor runtime through the runtime pack's `armada-node`, ADR 0046, ADR 0054), plus the machine commands (`init`, `join`, `doctor`, `backup`, `restore`, `runtime`); `armada` is the client that only talks to the API (no root, Linux and macOS). Ingress uses HAProxy as a system container managed by Armada.

- **Architecture decisions:** `docs/adr/`. **Threat model:** `docs/threat-model.md`

When the design changes, add or update an ADR in the same change. Never let code and documents contradict each other (see "Keeping documents current" below).

## Architecture in brief

The design below was written while the code was Go, and the Rust code is a port of it, file for file, so its names (camelCase functions and types, Go package paths such as `internal/server`) name the Go code that was removed (ADR 0055 item 20c); the Rust code has the same parts in snake_case. Where they live now: `internal/server` → `server/src` (one file per Go file, e.g. `reconcile.rs`, `ingress.rs`, `runtimemove.rs`), `internal/store` and the client side of `internal/etcd` → `store/src`, `internal/agent` → `agent/src` (the sessions beside the pass in `agent/src/side`), `internal/cli` and `internal/clientconfig` → `client/src` (`config.rs`, `dial.rs`, `release.rs` for `internal/release`), `internal/daemon`, `internal/backup`, and the member side of `internal/etcd` → `daemon/src`, `internal/spec` → `spec/src`, `internal/pki` → `pki/src`, `internal/secrets` → `secrets/src`, `internal/fsutil` → `fsutil/src`, `internal/certs` → `server/src/certs.rs` and `server/src/acme`, `internal/alert` → `server/src/alert.rs`, `internal/proxy/haproxy` → `node/src/proxy` (the renderer) and `agent/src/haproxy` (the driver), `internal/clusternet` → `node/src/net` and `agent/src/clusternet.rs`, `internal/runtime/...` → `agent/src/supervisor` and `node/src/runtime`, `internal/volbackup` → `node/src/volbackup`, `internal/conntrack` → `node/src/conntrack.rs`, `internal/queuelen` → `node/src/queue`, `internal/logexport` → `agent/src/side/logexport.rs`, `internal/dnsserver` → `dns/` (armada-dns) and `agent/src/dnsprocess.rs`. What the Go code had and the Rust code does not: every fallback to Go's own code when armada-node fails (the agent fails the call instead), the `netAgent`, `runtimeAgent`, and `volumeAgent` opt-outs in `agent.json` (ignored; doctor warns on `runtimeAgent`), the userspace WireGuard device (the cluster network needs the kernel's), the in-process resolver (armada-dns only), embedding etcd and the agent in `armadad server` (`armada-etcd` and `armada-agent` run as units), the containerd runtime on nodes (the agent starts nothing on a containerd node; v0.1.0-alpha.42 moves them first), and Go's runtime tuning (`GOGC`, Go's runtime metrics).

- **Desired state + reconciliation**: the CLI only writes desired state to the server; reconcilers on the server and agents converge actual state. Every operation goes through this path; never add a "just run the container" path from the CLI.
- Agents open the gRPC (mTLS) connection to the server; the server sends assignments over a bidirectional stream.
- Nodes (ADR 0003): joining goes through a separate join listener (server-only TLS, serves only `JoinService`, rate limited, connections bounded before TLS by `connLimit` (256, 16 per source) and closed after 15 s idle or 2 min; `Config.JoinListener`/`JoinIdle` in tests); the main API is always strict mTLS. The joining node pins the CA by hash without `InsecureSkipVerify`. Node certificates last 30 days, are renewed by the agent, and are only accepted while their serial is recorded in `node_certs` (removing a node revokes them; `RemoveNode` first queues an empty assignment on the node's session, which the send loop flushes before it ends (`flushSession`), so the removed agent stops what it ran). Each server renews its own server and etcd member certificates (`certRenewer`: at start before loading, then every 12h, `pki.RenewDue` = last third or expired) with `CA.Reissue` (same key, one file written atomically); `pki.ServerCert` serves the current one on every handshake (API, join, metrics), and etcd and `clientTLS` read the member files per handshake. Before the embedded agent starts, `certRenewer.renewNode` re-signs the machine's expired node certificate (recorded with `RecordNodeCert` first; a removed node is refused), otherwise the agent, and with it the server, could not start. Admin certificates: `armada admin renew` (`RenewAdminCertificate`, caller's own name, audited) or `armadad admin renew` with the CA on disk; doctor's `certificates` check warns and fails on expiry. Cordoned nodes get no new replicas and are evacuated without dropping below the desired serving count. Unevenly spread apps are rebalanced one replica at a time across the cluster through the same path (ADR 0013). Placement (ADR 0014): admin-only node labels (CLI or join token; `armada.os`/`armada.arch` reported by the agent, `armada.site` from `Node.Site` (ADR 0050: `JoinToken.Site`, `SetNodeSite`, audited, `SiteChanged` event; empty = the first site, no label), `armada.` reserved), restricted nodes, `placement.require`, and `placement.spreadBy` (soft: even over a label's values, then nodes; yields to capacity; only labelled nodes; rebalancing compares values first, then nodes within a value); every scheduling path (scale, rollout, self-healing, evacuation, rebalancing) only picks nodes from `eligible()`, and replicas on nodes that stop being eligible move like cordoned ones. Image platforms are learned from agents after a pull (or from the registry when the image has no variant for the node; `runtime.PlatformError`), kept once per revision like the digest, and restrict `eligible()`; the control plane never contacts registries. Replicas reserve CPU (`resources.cpu`, default 100m, also the limit when set) and memory with no overcommit; `allocatable()` subtracts what Armada keeps (100m CPU and 128Mi per node, 100m more on servers) before `pickNode`, and capacity only fits and breaks ties, never outranks the replica count (T28). `pickNode` also skips a node with its own subnet at `maxSubnetReplicas` (250, `replicasFull`;
finished job attempts hold no address). A replica that has kept failing to start for a minute, outside a rollout, is replaced on another node that fits (`moveFailed`, one per app at a time). A pass works out once what each app needs to know about all the replicas (`reconcileRun.view`, `replicaView`: replicas per app, `placedUse` per node), again only after a change, so its cost does not grow with apps times replicas. `ReplicaSpec.cpu_reserve_millis` sets the container's CPU weight and stays out of the agent's spec hash.
- Internal ingress (ADR 0007): `<app>.internal` is served by a HAProxy `frontend internal` bound to the container bridge gateway (`armada0`) (never the private IP: NAT and load balancers make that reachable from the internet) and resolved by the node's resolver on the same address: `armada-dns` (ADR 0053; `dns/`, Rust std only, in the runtime pack as `embedded.BinDNS`; `dnsserver.Process` runs it with `systemd-run` as `armada-dns-<hash of program and settings>` (`Restart=always`) so it outlives `armadad`, reuses a running unit, and talks to it over `/run/armada/dns/<hash>.sock` (one line per connection: `names`, `clients`, `epoch`, `state`, `drain`), sends everything again to a process with a new epoch (`Process.keep` every 5 s); a new unit reads the old one's state (`--take-over`) before binding with `SO_REUSEPORT`, then the old one drains (its UDP socket connected away, held lookups answered) and stops (`handOver`); UDP is an epoll loop per CPU (≤4, `dns/src/udp.rs`) forwarding each lookup on its own socket; `startInternalDNS` falls back to the in-process `dnsserver.Server` when the pack has no `armada-dns` or it does not start; `runtime reset` stops the units (`dnsserver.StopUnits`)), else the Go `internal/dnsserver` in `armadad`, with the same rules: which answers only the bridge subnet and forwards other names at most 128 at a time, 16 per client address (`maxInflightPerClient`, checked before the node pool), with at most 16 TCP connections per client (`clientListener`). Names alone within a space: the agent gives each container `runtime.ContainerSpec.DNSSearch` = `spec.InternalSearchDomain(app)` (`internal` or `<space>.internal`, checked by `spec.ValidSearchDomain` in `CheckContainerSpec`; outside the spec hash), which the embedded runtime puts first in one merged `search` line (`resolvConf`, at most 6), and the internal frontend completes a `Host` without a dot with the caller's space (`txn.cspace`; `.internal` alone without a clients map). Internal and public rules never mix; the `.internal` zone is reserved.
- Container runtime (ADR 0011, ADR 0046): every node runs the supervisor (below); containerd has left the runtime pack (ADR 0055), and `armada-runtime.service` runs `armadad runtime`, which extracts and verifies the pack and exits (on a containerd node it fails, naming v0.1.0-alpha.42's move). What follows describes Go's containerd driver up to v0.1.0-alpha.42: nodes set up before ran Armada's own containerd from binaries pinned in `pack/lock.json` and embedded in release builds, which `armadad runtime` exec'd (own root, socket `/run/armada/containerd/containerd.sock`, namespace `armada`, config format 4 with `imports = []`, no CRI/NRI/TCP/debug/metrics, restart monitor disabled). `internal/runtime/containerd` builds the OCI spec itself (shared checks in `runtime.CheckContainerSpec`), uses CNI (`armada0` with a fixed MAC from `bridgeMAC`, host-local IPAM on tmpfs with a default route, portmap on the private IP, firewall); every address given back (`cniNetwork.Teardown`: Remove, `ReleaseNetwork`, sandboxes) has its host conntrack entries deleted right after CNI DEL (`forgetAddr` → `forgetConnections`, netlink `ConntrackDeleteFilters` on original source/destination and either reply address, address read from the plugins cache first; failure only logged), since isolation accepts established flows first and the address may go to another space next, app containers and their members run at OOM score adjustment 0 (`appOOMScoreAdj`, not their shim's -999) and `armada-server`/`armada-agent` at -500, so the kernel kills workloads before the node's daemon; the AppArmor profile is (re)loaded when the agent starts (`runtime.AgentStarter`, `Driver.AgentStart`; not from `Ping`, which doctor also calls), unique container IDs per creation (`<name>-<hex>`), one shim per app and runtime pack on a node (`shimGroup`, annotation `io.containerd.runc.v2.group`, a name kept from containerd whatever the OCI runtime), and logs through one process per container that the shim runs: the pack's `armada-log` (`logger/`, Rust, standard library only, under 1 MiB; `Driver.logIO`, `embedded.BinLogger`; `armada-pack bundle --logger` checks its ELF architecture), else `armadad runtime-log` (`embedded.WriteLogs`, the reference `TestArmadaLogMatchesGo` compares against; `armada-log` alone keeps draining after a write error): rotation at `runtime.LogMaxSize`×`LogMaxFiles`, and a token bucket of `LogRate` 1 MiB/s with `LogBurst` 4 MiB per container; excess is dropped, never blocked, and counted in one stderr line when output fits again or at close). `agent.json` records `"runtime": "embedded"` or `"supervisor"` (any other value is refused: remove and rejoin the node). Supervisor runtime (ADR 0046, the default for new nodes (`defaultRuntime`; an agent.json with no runtime stays on containerd), `--runtime embedded|supervisor`, `armadad runtime migrate`; doctor warns on containerd nodes): the driver reaches containers through `backend` (`internal/runtime/containerd/backend.go`: the containerd client, or `supervisor.Store`, which implements containerd's `client.Container`/`Task`/`Process`/`Image`), so everything else in the driver is shared; `internal/runtime/supervisor` keeps images without a daemon (`Images`: containerd's local content store, overlay snapshotter, and layer applier in process, `pullParallel` 2, `images.json`, `Delete` collects unused layers and blobs), OCI bundles (`Bundles`: rootfs mounted from a snapshot prepared before the spec, `config.json`, `record.json` last), and `armada-shim` processes (`Shims`: one per spec group as a transient systemd unit `armada-shim-<hash>` via `systemd-run`, socket `/run/armada/shim/<hash>.sock`; unit limits as `armada-runtime.service` (`LimitNPROC`/`LimitCORE`/`LimitNOFILE`/`TasksMax` infinity, `OOMScoreAdjust=-999`); `For` and `Abandon` hold a per-group lock (`Shims.lock`); `abandon` kills and deletes what a shim left in its runc root only once it is gone (`Shims.gone`: socket ENOENT/ECONNREFUSED, or its unit not active per `Shims.Active`, default `systemctl show ActiveState`), never for a timeout or EOF, so `container.Task` returns the error and the next pass asks again); exec is `runc exec` in the foreground from the agent (pty for `-t`; started with no signal blocked from a locked thread (`startUnmasked`); `Kill` signals only a pid above 1 within int32, else NotFound; a SIGKILL, or a `Delete` whose context ends first (`abandon`), metrics are read from cgroup files (`readCgroup`). `armada-shim` (`shim/`, Rust std only, `extern "C"` prctl/waitpid/kill/dup2/fcntl): subreaper, the OCI runtime's `create/start/kill/delete` (crun, or runc for a container runc created: ADR 0056, below), `armada-log` on fds 3/4/5, one request line per connection (`create`, `start`, `state`, `wait`, `kill [all]`, `delete`, `list`), exits 10 s after its last container (`IDLE_EXIT`); refuses a pid ≤ 1 from the runtime's pid file and `delete --force`s a container whose pid file fails (`parse_pid`); keeps at most `MAX_EXITS` (4096) unclaimed exit codes, oldest past `EXIT_GRACE` dropped first, containers' pinned (`Exits`). On supervisor nodes the agent installs the pack (`installPack`) and `armadad runtime` exits.
- OCI runtime (ADR 0056): crun creates every new container; runc stays for the containers it created before, which crun cannot manage, until they are recreated (and leaves the pack in a later release). `node/src/runtime/container/oci.rs` (`OciRuntime`: `NEW` = crun, `of_record` reads a bundle record's `runtime`, none = runc, an unknown name refused; `root` = the runtime's own `--root` under the shim's state, `/run/armada/shim/<shim>/crun` beside `.../runc`). The bundle record (`bundle::Record.runtime`, `CreateRequest.runtime`, omitted when empty) names the runtime; the agent (`agent/src/supervisor`: `Shims.crun`, `Shims::root(group, rt)`, `Shims::program(rt)`) sends `create ID BUNDLE LOGDIR crun` (no word = runc, as an agent before asks) and gives exec sessions, probe and queue commands, and system execs the record's runtime and root (`exec::ExecRequest`/`SessionRequest` `runtime` + `program`; armada-node's exec request key `runtime`, `runc` read as its alias; texts name the runtime: `exec: crun exec: fork/exec ...`, `exec: crun exec did not start the process`). `armada-shim serve SOCKET STATE RUNC ARMADA-LOG [CRUN]` (crun last and optional: shims of a release before run runc alone) remembers each container's runtime for `start`, `kill --all`, and `delete --force`, with errors naming it (`crun start exited with 1: ...`); a new app container goes to a shim of the new pack (the group names the pack), so a running shim never gets containers of the other runtime from an older agent. A gone shim's containers are ended in both roots, each with its own program (`Request::abandon_root`: runc's, then crun's; a crun root with no crun program is an error). The pack carries crun's static `-disable-systemd` release build (Armada's cgroup paths are cgroupfs paths, `/armada/<id>`, and it never asks for `--systemd-cgroup`), `daemon/src/pack.rs` `BIN_CRUN`, and `armadad runtime --bin-dir` needs crun beside runc. crun takes the arguments runc took with the same meanings (ADR 0056 lists them); it differs in `kill --all` of an ended container (success, where runc fails), writes pid files in place, and with a terminal of its own clears output translation, so crun's exec with a terminal runs with `--console-socket <exec dir>/console.sock` (`ExecRequest.console_socket`, request key `consoleSocket`, set by the agent for crun only): `armada-node` binds it through the directory's descriptor (`console_listener`), takes the container's terminal master over SCM_RIGHTS (`await_terminal`, `recv_terminal`: a terminal or nothing, within the start's limit or crun's end), copies and resizes through it, and copies crun's own stdout and stderr to the caller's output; runc's own terminal is unchanged (`node/tests/exec_console.rs`: a python3 stand-in crun sends a master, "\r\n" reaches the caller; the conformance suite checks it on crun). Where the bullets below say runc for the supervisor runtime's calls, the call goes to the container's runtime.
- Admin config (ADR 0027): `armadad init` writes `clientconfig.SystemPath` (`/etc/armada/admin.config`, root:`armada` 0640 via `SaveShared`, `/etc/armada` gets o+x only); `clientconfig.DefaultPath` = `$ARMADA_CONFIG`, else `~/.armada/config` if it exists, else the system path; `Load` accepts group read only for root-owned 0640 group `armada` (`sharedOK`); `Config.SSH` (ADR 0048): every connection runs the user's `ssh -o ExitOnForwardFailure=yes -W ADDR -- DEST` (`sshDialer`, `SSHProgram`, a net.Conn over pipes with deadlines, ssh's last stderr line in errors; `CheckSSH` refuses option-like or shell destinations; the config's servers only, no machine list; tests use the `clientconfig/sshtest` stand-in, which reaches only `bastion.test`); `SaveFile` keeps a shared file shared; the installer creates the group. Run through sudo, init and `server join` add `SUDO_USER` to the group (`joinAdminGroup`, `groupCommand`: `usermod -a -G`, else `gpasswd -a`, else BusyBox `addgroup`, also looked up in the sbin directories; failure only warns; they print to log in again or `newgrp armada`) instead of copying the file to the home, and init names the first user (cluster-admin) after them; each server renews the user certificate in its own shared file (`certRenewer.renewAdmin`, only as root from the default data directory, at start and every 12h once `pki.RenewDue`, new key, signed by the CA and recorded with `RenewedUser`, so a deleted or replaced user stays out; `SaveFile` keeps it shared); an unreadable shared file says whether the account is outside the group or joined after the session started (`groupAdvice`).
- Access control (ADR 0033): principals are users (`pki.KindUser`, one year, `SignUserCSR`) and services (`pki.KindService`, 90 days, `SignServiceCSR`); `Identity.Principal()` reads the old kinds `admin`/`automation` as user/service. `store.Principal` records under `users/` and `services/` (schema 9, `migrateAccess` moves `admins/` and `automation/` without changing rights) hold `Roles []Grant` (role + space, "" = cluster; `CheckGrant`: `cluster-admin`/`space-creator` cluster only, `deployer`/`admin` one space and never `default`, `viewer` either) and allowed node `Labels`. Users: `Since` + `SinceSerial` + `Cutoff` (`principalRec.userAllowed`: the certificate a replacement recorded, by serial, and ones issued (NotBefore + `pki.ClockSkew`) in a later second than the record was written; older records compare NotBefore with `Since`), deleted = tombstone; `RenewOwnCertificate` for users signs, then `RenewedUser` checks the caller and audits in one transaction, rate limited per name (`userRenewLimit`); `UserAccess` gives a name with no record cluster-admin only for a certificate issued (NotBefore + `pki.ClockSkew`) by `meta/user-cutoff` (schema 14, `migrateUsers`, kept when it exists) or while the keyspace is older; a keyspace created at 14 refuses every such name, and `RenewedUser` applies the same check (`etx.unrecordedUserAllowed`), so a user lost in a restore is refused. Everything that signs a user certificate outside the API records the name first with `KnowUser` (cluster-admin unless on record): init, `armadad user renew` (`recordUser`, through `stateClient`), and `armadad server join` (`JoinServerRequest.user_name`, recorded by the leader's `JoinServer`; `joinedClientConfigs` writes nothing without `user_recorded`). Services: recorded serials (`RecordServiceCert`, keep = renewal), `ServiceAccess`. `authorizePrincipal` (`internal/server/auth.go`, `methodAccess`) reads roles on every call, and `streamGuard` (`streamguard.go`, started by `streamAuth` for principals) again every `Config.StreamRecheck` (5s) while a stream is open, also at the certificate's NotAfter: a refusal cancels the stream's context and the stream ends with that error; handlers register their app/node checks with `requireAccess`, Events filters with `streamAccess` (the latest access), and Logs calls `recheckAccess` before following a new replica: cluster-admin calls every `AdminService` method; others only methods in `methodNeeds` (`access.go`: `needView`/`needDeploy`/`needAdmin` space levels, `needCreateSpaces`, `needSelf`; anything missing is cluster-admin only, tested over the whole service descriptor) that a role `reaches`; handlers check spaces through `accessFrom(ctx)` (`app`, `space`, `sees` against the method's level; `creates`; `placement` against the labels; `admin()` = cluster-admin or `internalContext`). RPCs (`rbac.go`, cluster-admin only): `CreateUser`, `IssueUserCertificate`, `CreateService`, `IssueServiceCertificate`, `ListPrincipals`, `UpdatePrincipal`, `DeletePrincipal`, `CreateAssignment`, `DeleteAssignment`, `ListRoles`; `RenewOwnCertificate` for any principal. Nobody deletes themselves or drops their own cluster-admin. `CreateSpace(.., by)` makes a space-creator `admin` of the new space in the same transaction; `DeleteSpace` takes every role in it back (`forgetSpace`); for non-cluster-admins `Events` and history searches leave out what a space's apps left before the space was created (`spacesCreated`, `beforeSpace`), so a recreated name shows nothing of the earlier space. Non-cluster-admins get no nodes and no cluster events.
- Platforms: Armada runs on Linux only (linux/amd64 and linux/arm64 releases); only the `armada` client also builds for macOS (darwin archives, client-only `install.sh`); Linux releases also carry a client-only archive (`armada-client_<version>_linux_<arch>`) that `install.sh` uses with `ARMADA_CLIENT_ONLY=1` (falling back to the full archive for older releases), and a full install puts both binaries as separate files; Windows has no native client, the docs point to the Linux client in WSL 2. Binaries (ADR 0027): the daemon (`daemon/`, `armadad`) holds every command that runs on a machine; the client (`client/`, `armada`) only talks to the API and never links the daemon or what a machine needs (`client/tests/dependencies.rs`); the daemon reuses `cli.Run`, `cli.RPCError`, `cli.ReadSecretValue`, `cli.NewVersionCommand`. Tests that run a server in process and drive client commands live in `internal/daemon` (`execute` sends each command to the binary that has it). Removed `Hello` fields (`runtime`, `min_memory_bytes`) are reserved in the proto.
- Command line (ADR 0032, ADR 0052): `armada NOUN VERB` and nothing deeper; the root holds only nouns and `version`, listed in four groups (Apps, Cluster, Access, Monitoring: `cobra.Group`, `listGroups` in `usage.go`); no old names or aliases beyond `ls`/`rm` and plural nouns, and the words before ADR 0052 fail with `unknown command` (`TestCommandAliases`). `app deploy` and `job deploy` (`internal/cli/appspec.go`: `specFlags`, `runDeploy`: `--new` = `runCreate`, else `runUpdate`, which creates what does not exist) build a `spec.App` from flags (or read `--file`, with `--vars`/`--var`), validate it with `spec.ParseIn` after `Export`, and send `DeployRequest` with `must_create`, or `must_exist` + `base_revision` (the revision `GetAppSpec` returned; flag updates only), so a change in between is refused; `--diff` prints a line diff (`diff.go`) of the exported specs and deploys nothing. `app show`/`job show -o yaml` print `GetAppSpec` as is. `app list` follows `ListApps`' `next_page_token`; `cluster status` is `ClusterStatus`. `Status` with an app (`app show`, rollout waits every second; `appStatus`) returns that app and no nodes, reading its own replicas (`ReplicaFilter{App}`), the node records, and only its own domains (`appURLSource`); every replica and the servers (`allocatable`) only when `placementNeedsCluster` says its placement message compares with them. Other read paths stay in a few batches whatever the cluster's size: `ListVolumes` (`mountedVolumesOf`: `store.GetApps`, then `GetRevisions` for targets), `ListJobs` (runs grouped by job), `ListSpaces` (counts from `store.ListAppIDs`, keys only). The space: `--space`, else `ARMADA_SPACE`, else `clientconfig.Config.Space` (`space use`, checked with `ListSpaces`), else default (`globals.resolveSpace` in the root's `PersistentPreRunE`); `-A` spans spaces in lists. Output: lists print a table only, actions one line of what happened, `-o json` (protojson) on everything that prints data (`outputFlag`); `dialAdmin` is a variable so tests drive commands against a fake client. `explain` (`usage.go`, run by `Run` on both trees) replaces cobra's argument errors with the missing placeholders of the Use line (or how many are too many; never an argument's value, which may be a secret) plus the usage line, points flag errors to `--help`, and lists each verb with its arguments in a noun's help. `replica list` (`replicas.go`) reads `Status`; `app exec` runs `defaultShell` without a command and sets `-i`/`-t` from the terminal unless given. Unknown verbs print a `verbHints` line (`app scale`, `secret get`, ...); `secret show` of a missing secret names the space's secrets (`noSecret`, `choiceList`, at most `maxChoices`). Completion (`complete.go`, `completeFromCluster`): each positional argument's `completer` comes from its Use placeholder (`argKinds`, `placeholderKind`: APP, JOB, RUN, SECRET, KEY, REVISION, REVISION=WEIGHT, NODE, SPACE, ROLE, VOLUME, DOMAIN, NAME by noun, nothing for `create`), flags from `flagKinds` (`--replica`, `--container`, `--to` under app; `--run` under job; `--space`, `--node`, `--role`, `--user`, `--service`), each asking the cluster through `dialAdmin` within `completeWait` (5s); it never offers a secret's value. `RPCError` passes every line of a status message through `printable` (control characters replaced, line breaks kept); the leader relays agents' volume errors through `cleanMessage`.
- Starting replicas (ADR 0011): `Agent.Reconcile` decides without starting anything, then `startPending` starts at most `maxConcurrentStarts` replicas at once, each image pulled once per credentials (`pullOnce`, for that set of starts only); the embedded `Driver.Pull` uses a digest-pinned image on the node without the registry only when `pulledWith` its labels (`armada.pulled-with/<pullKey>`: SHA-256 of registry, user, password, or `anyone`), else `resolver.Resolve` checks the credentials first (`markPulled`); the resolver (`newResolver`, `guardRegistryClient`) sends every registry, redirect, and token request over HTTPS only, drops the other URLs a manifest lists for a layer (`registryOnly`, `noForeignURLs`: containerd would fetch them with `http.DefaultClient`), follows at most 10 redirects, uses an HTTPS proxy only when the environment names one, and dials no link-local, unspecified, or multicast address (T83); a pull of any name uses a blob its own fetcher did not download (already on the node, or written by another pull at the same time) only when an image `pulledWith` the same key holds it, else fetches it again from its own registry and checks its digest (`proveContent` returns a recording resolver the pull must use and a handler wrapper both backends run around each descriptor); both backends fetch every layer blob and keep an image only once each blob decompresses to its config's diff ID (`internal/runtime/imagecheck`, label `containerd.io/uncompressed` or read once; containerd: `WithUnpackFetchAllContent`, `containerdBackend.CheckLayers`, the image deleted on failure, and a digest-pinned image on the node that fails it is pulled again; supervisor: `Images.unpack` checks layers whose chain exists before recording, `verified` in memory), since unpacked layers are found by diff IDs alone. Supervisor `Images.Pull` holds `pulls` shared; `Delete` collects unused layers and blobs only when no pull runs (`collectIdle`, else the last pull to end), and a name re-pulled to another target drops its labels. Every `startReportInterval` it applies the firewall for finished starts, applies proxy changes, and sends a report of the rest; a replica starting for the first time is left out, and one whose container is being recreated (`pendingStart.replaced`: crash, liveness, spec change, machine restart) is reported `starting` with no address and its old container ID (`Agent.recreating`) from the first report, sent before any start, so its old address usually leaves the proxies before the node hands it to another container (nothing waits for the proxies; a quicker start is caught by `claimedTwice`, and the firewall and internal frontend still check the caller). A replica's `AddressConflict` (and every other condition of an app or job) ends when it is deleted (`endAppConditions`). `RemoveNode` queues the final empty assignment with `session.endWith`, dropping queued messages to make room. `forgetConnections` reads the conntrack table again (up to 5 times) when the kernel interrupts the dump. `Driver.Run` holds its lock only for replicas that publish a port. Every `ImagePrune` (10m) the reconcile loop calls `Agent.PruneImages` under `reconcileMu` (after the first assignment): `runtime.ImagePruner` removes images no container in the namespace uses, not named (reference or digest) by the assignment or `digests`, and not pulled within `imagePruneGrace` (1h); the last delete is synchronous so containerd frees content.

- The cluster network through armada-node (ADR 0054 step 3, the default): unless `agent.json` has `netAgent: "go"` (`agentConfig.netProgram`, `netAgentGo`; any other value or none = armada-node), the node gets `clusternet.Config.Program` = `packProgram(dataDir)` (`meshConfig`, so the agent and `upMesh` alike), and doctor and `runtime reset` use `DiagnoseWith`/`RemoveWith`. `Net` (`program_linux.go`) then runs `armada-node net apply|up` (`viaProgram`, `pass`) with what it keeps between passes as JSON state (`programState`/`takeProgramState`: clean flags, switch state, `wgSince` in Unix seconds, the last summary; the isolation policy is kept per side, `prog.previous`, and a pass after the other side's rebuilds the tables, `takeOver`), `net unreachable`, `net key rotate`, `net diagnose`, `net remove`; a pass armada-node fails, cannot be read from, or answers `needsUserspace` for is done by Go's code at once (`goApply`; full idempotent sync), logged once per distinct error per call (`note`), and while the userspace WireGuard device runs (always Go's) armada-node is not asked. - HAProxy: structural changes (new app/domain/route) = re-render + `haproxy -c` + reload (`Driver.reload`: SIGUSR2, then waits until `show info` names a new process, at most `reloadWait` 10s, so live changes after it reach the new process; a timeout makes the next Apply reload again); deploy/scale/drain/certificates = Runtime API over a Unix socket (`set ssl cert` payloads go through `pemPayload`, which drops the empty lines issued bundles have between blocks; a live certificate update that still fails reloads HAProxy, which reads the new file). Do not use the Data Plane API. Long-lived connections: `timeout tunnel 1h`,
`hard-stop-after 1h`; `ingress.timeout` → `proxy.Backend.TimeoutSeconds` renders `timeout server` in the app's backend. A new agent takes over a running proxy with no reload when the configuration differs only in server lines (`liveConfig`, `sameStructure`; slots from `show servers state`, the same certificate names). Local-first routing (ADR 0024): `proxy.Backend.LocalFirst` (`ProxyBackend.local_first`, set by `buildProxy` unless the app splits traffic) makes `be_<app>` `balance leastconn` with each server weighing `localWeight` (11) on the node's private IP or in its container subnet and `remoteWeight` (10) otherwise (`backendPool`), set through the Runtime API like an address. Idle servers tie, so the backend's own `use-server` rule picks a local slot from `local.map` (`localMap`, `replaceMap`) while `be_conn` is at most 1, for requests from the internal frontends only (`!{ fe_name http } !{ fe_name https }`, `frontendHTTP`/`frontendHTTPS`): public requests arrive at one node often and would all stay on it at low load, so they balance over every replica. Nothing about local-first reloads the proxy or adds a frontend rule; every `http-request` rule is written before the `use_backend` rules. A rule that matches a whole host with no `ingress.allow` and no wake needs no rules of its own (`mapped`): `routeMap` writes it to `routes-<frontend>-<hash>.map` (0600, named after its content, `<space>/<host>` keys on the internal frontend so another space's caller finds no route), and `use_backend %[var(txn.route)]` picks its backend, so a request's cost does not grow with the apps of the cluster. `Layout` is keyed by HAProxy backend name; `parseLoad` reads `be_` rows. `Driver.Load` keeps `ServerLoad.Total` growing across reloads: `Apply` reads it just before a reload, and when `show info` names another process the latest totals carry over.
- Rollouts (ADR 0005): an app has an `active_revision` (serving) and a `target_revision` (rolling out). Agents decide readiness through probes, HTTP or a `command` run like `armada app exec` (`checkCommand`; output dropped, arguments never logged) (a container older than the agent stays out of reports until a first verdict, `awaitsVerdict`; the implicit port check slows to about 10 seconds once ready, `implicitPeriod`); the server only puts `running` + `ready` replicas in the proxy, retires old replicas after the warm-up, and deletes them after the drain timeout (`drain` in the spec, default 10s, `drainFor`), counted from the later of `DrainingSince` and the leader's `termStart`, and held up to `awayHold` (1m) more while a node is away (`reconcileRun.away`: disconnected, not lost), except for apps with volumes (`finishDrain`'s hold). Never delete a replica that serves traffic without draining it. The agent applies the proxy before removing containers it no longer wants (`Reconcile`, strays), reconnects every `failoverRetry` (1s, jittered) for `failoverWindow` (2m) after a session it had ends (`reconnectWait`), gives up on a session the server does not answer within `sessionAnswer` (10s), and the gRPC channel's backoff is capped at 1s (`clientconfig.Dial`).
- Removing an app: `RemoveApp` sets `appRec.Removing` (`MarkAppRemoving`, audited; refused for jobs); the leader's `reconcileRemoval` retires its replicas through the normal drain and calls `DeleteApp` (revisions and secrets, in one transaction, only with no replicas left). Deploy refuses a name being removed. Volumes stay, so `armada volume delete` works with the app gone, and a space holding them cannot be deleted until then.
- Secrets (ADR 0006, ADR 0052): a secret belongs to a space and holds keys; it is named by an ID like an app's (`spec.AppID`), and the secret with an app's ID is that app's own, so the layout of before is unchanged: `secrets/<ID>/<key>/<version>`, `secretseq/<ID>/<key>`, and the RPCs `SetSecret`/`ListSecrets`/`DeleteSecret` (their `app` field is the secret's ID, `name` the key; `DeleteSecret.whole` deletes every key), plus `ListSpaceSecrets`. A spec reference (`spec.ValidateSecretRef`) is `KEY` (the app's own secret) or `SECRET/KEY` (`spec.SecretSource` resolves it within the app's space; another space is never reachable); keys are `spec.ValidateSecretKey` (a secret name or a variable name). Revisions pin each reference as written (`rev.Secrets["db/url"]`), and `Deploy` records the app under `secretusers/<secret ID>/<app ID>` (`noteSecretUsers`) for every other secret it pins, so `secretPins` (pruning, `servingPins` for deletes and `ListSpaceSecrets`, `ListSecrets` used-by, `SetSecret` rollouts of every app whose target revision uses the key, `checkSecretBackups`); `RestartApp` (`Etcd.RestartApp`, `deployRevision` with force: a new revision of the target spec with the latest versions even when nothing changed; refuses jobs, traffic splits, apps being removed; the server runs `checkStoredRevision` and `checkBackupTargets` with the latest values first, audits `app.restart`, records `Restarted`) reads only those apps' revisions and drops entries of apps that pin none any more; `DeleteApp` keeps the app's secret while another app pins it. Deploying a spec that `UsesSpaceSecrets` needs schema 15 (`needSchema`: every server upgraded), since an older leader would read `SECRET/KEY` as a key of the app's own secret; `TestLegacySecretsAssignmentUnchanged` compares a replica's spec with one written by the release before (`testdata/legacy-secrets.golden`). Values are encrypted with `internal/secrets` (envelope AES-256-GCM, master key `master.key`, the secret's ID and key as scope and name). The server decrypts only while building a node's assignment, and keeps the versions it opened in memory across passes (`openedSecrets`, dropped once no pass uses them, `forget` on DeleteSecret; never in etcd or logs); versions are never reused (`secretseq/<app>/<name>` keeps a deleted secret's last version), and done or draining replicas whose pinned version is gone get `unresolvedSecrets` (the reference only); the agent writes secret files only to its tmpfs secrets directory. Never log `ReplicaSpec`, `Assignment`, or `SetSecretRequest` (their `Debug` prints every field), and never put secret values in container labels or the spec hash.
- Armada's containers and resources are identified by `armada.*` labels and must be idempotent: an agent can restart at any time and adopt existing containers. Go's `armadad server` runs the node's agent in its own process (`--agent`); the Rust release runs it as `armada-agent.service` on server machines too (ADR 0055: `armada-server.service` wants it, and the Rust server runs no agent and takes no lock). The harness (`parity_side_test.go`, `TestAgentParitySide`): `sideServer`, AgentService's ExecSession, PushLogs, and VolumeSession over mTLS, recording each stream (archive data as its total) and sending scripted input; the fake armada-node is the test binary run again (`TestMain`, `ARMADA_FAKE_NODE_ROOT` through a wrapper script in the run's directory) answering from `script.json` and logging each call with its request to `node.log`; `exportServer` records gunzipped requests; pfake gains the sessions' runtime calls (`execSession`, `logs`, `searchLogs`, `pruneLogs`, `tailLogs`, `tailLogsEncoded` through `pfakeEncoding`, `commitLogs`, `readQueue`, the sandbox calls; `answerSide`); `parityRun.side` and `sampleSide` record them.

## Code conventions

- Everything is in **English**: code, identifiers, comments, commit messages, error messages, and all documentation (open source project for a global audience).
- Licenses (mandatory): Armada is Apache-2.0 and must stay free for commercial use. `armada-log` (`logger/`), `armada-shim`, and `armada-dns` use the Rust standard library only (`armada-pack`'s notices tests), and the notices name the libraries they link statically (Rust std, musl); the Cargo workspace at the root (ADR 0055: `armada-node` in `node/`, ADR 0054, `armada-proto` in `proto/`, and `armada-fsutil`, `armada-pki`, `armada-secrets`, `armada-spec`, `armada-store`, `armada-server`, `armada-client`, `armada-agent`, `armada-daemon`, `armada-pack` (the pack's build tool, never shipped) in `fsutil/`, `pki/`, `secrets/`, `spec/`, `store/`, `server/`, `client/`, `agent/`, `daemon/`, `pack/`) may use crates only under Apache-2.0, MIT, BSD-2-Clause, BSD-3-Clause, ISC, MPL-2.0, CC0-1.0, or Unicode-3.0 (Unicode data), checked from the root `Cargo.lock` in CI (`deny.toml`) and listed in `THIRD_PARTY_NOTICES.md` (`armada-pack`'s notices tests), their license files in release archives (`scripts/rust-licenses.sh`, `third_party/licenses/rust/` for a crate published without one); `proto/gen` (the generator of `make proto`, never distributed) keeps its own lock outside the workspace; never GPL, AGPL, SSPL, BUSL, or anything that limits commercial use in Armada's own programs or anything they link, and no copied code under such licenses. One exception (ADR 0056): a program under the GPL may be in the runtime pack when Armada's programs only run it as a separate process (never link it or any of its code) and the release carries its complete corresponding source and its license, pinned in `pack/lock.json` (`license`, `sources`: crun's release tarball and the build files of its static programs, each by SHA-256; `armada-pack sources`, `make runtime-sources`); `armada-pack`'s tests refuse a GPL pin without them, and AGPL, SSPL, and BUSL pins at all. Commercial use and running Armada as a service stay unrestricted. Do not change MPL-2.0 files of a dependency. Changing an embedded runtime program (`pack/lock.json`) updates `THIRD_PARTY_NOTICES.md` in the same change (`cargo test -p armada-pack`); its static libraries (glibc, libseccomp, and crun's libcap, json-c, libcriu, protobuf-c, libgcc) are listed there with their licenses and source. Release archives carry `LICENSE`, `THIRD_PARTY_NOTICES.md`, `third_party/licenses/`, `licenses/rust/`, and (full Linux archives) `licenses/runtime/`, the license files of the Go modules the pack's etcd programs link and crun's license texts (`crun@<version>/`), and `source/runtime/`, crun's complete corresponding source. Images Armada pulls at run time (HAProxy, GPL-2.0) run as separate containers and are never linked or bundled.
- Commit subjects follow Conventional Commits, `type(scope)!: description`, because the release notes are grouped by type (`.goreleaser.yaml`) and CI rejects other subjects (`scripts/check-commits.sh`). Types: `feat`, `fix`, `security`, `perf`, `docs`, `deps`, then `refactor`, `test`, `ci`, `build`, `chore`, `style`, `revert`; `!` marks a breaking change. Write the description for the people reading the release notes. `main` only changes through pull requests that pass every CI job (repository ruleset; see docs/releasing.md).
- Idiomatic Rust (edition 2024), `cargo fmt` and `clippy -D warnings` clean (`make lint`, with and without the test features); no `unsafe` beyond the system calls that need it. Error texts, outputs, and file formats are behaviour: the replays compare them with what the Go code did, so change them only on purpose, and change the recording with them.
- Code lives in the workspace's crates, one directory per crate at the root (`publish = false`: Armada has no public Rust API), and in `logger/`, `shim/`, and `dns/`; the protocol is `api/armada/v1/armada.proto`, generated into `proto/src/gen` by `make proto`. Test programs and hooks stay behind the `parity` and `test-hooks` features, never in a release.
- Every runnable command of both binaries has two to four examples a person can copy (`Node::example`, `client/src/cli`); help prints usage, examples, description, flags.
- YAML specs are parsed strictly (unknown field = error). Features whose types exist but are not implemented yet must be rejected with a clear message, never silently ignored.
- Tests live next to the code (`#[cfg(test)]` modules) or in each crate's `tests/`. Reconciler logic is tested with fakes, not a real runtime. HAProxy renderer changes come with their recorded cases (`node/tests/testdata/render.jsonl.gz`, by hand) and `make haproxy-check`.
- Development and CI always use ACME staging or Pebble, never the Let's Encrypt production endpoint.

## Keeping documents current (mandatory)

Every change updates, in the same commit or pull request, every document it makes stale. A change is not done until its documents are; do not leave it for a follow-up. Before committing, check at least:

- `README.md`: the short feature table and the document links; `docs/features.md` (full feature list) and `docs/tested-environments.md`.
- `docs/cli/`: run `make docs` whenever a command, flag, or help text changes (generated; never edit by hand).
- `docs/guides/`: the guides that use the changed feature (task recipes; every command and spec in them must stay valid), `docs/concepts.md` for changes to the core ideas, and `docs/README.md` (the documentation home) for new pages.
- `CLAUDE.md`: Status, Commands, Architecture in brief, and these conventions.
- `docs/compatibility.md`: what is stable and what is deprecated; a change to anything it calls stable needs a deprecation there first.
- `docs/`: quickstart, operations guide, spec reference, `threat-model.md` for anything that changes the attack surface or a mitigation, and `docs/adr/` for design decisions (a new ADR, or an update to the one the change supersedes, plus the index in `docs/adr/README.md`).
- CLI help text and error messages that describe the changed behaviour.

## Security rules (mandatory)

This is infrastructure software that holds root on every node. Treat these rules as merge requirements, not suggestions:

1. **Never weaken mTLS** (no certificate verifier that accepts anything, rustls' `dangerous()` included, no `--insecure` flag, no plaintext fallback), including for development or tests.
2. **User input into the HAProxy configuration** (domains, paths, app names) must pass whitelist validation in the spec crate (`spec/`) and be validated again before rendering (`agent/src/haproxy/config.rs`) and in the renderer (`node/src/proxy`). Never interpolate user strings into templates without validation, and never turn them into regular expressions.
3. **Secrets:** never print plaintext to logs, errors, CLI output, or the audit log. Secret types must redact themselves in `Debug` and `Display`. Never accept secret values as CLI arguments (they end up in shell history); read them from stdin or a file.
4. **Bind interfaces:** agent/server gRPC, internal DNS, HAProxy stats, and container ports bind only to private IPs. Only HAProxy on ports 80/443 faces the public; in a mesh cluster (ADR 0049) also the WireGuard port, and the leader's join listener only while a join token is open (T90); in a cluster with more than one site (ADR 0050) also the WireGuard port, and the leader's join listener on its endpoint only while a token for another site is open. Never bind internal services to `0.0.0.0`.
5. **Sensitive files** (CA key, master key, TLS private keys, `~/.armada/config`, state DB) are created with `0600`/`0700` permissions. Check permissions when reading them.
6. **Cryptography:** use ring (and rustls, rcgen, x509-parser on it) and ring's `SystemRandom`. Never invent cryptographic schemes. Compare tokens in constant time (`pki/src/join.rs`, `constant_time_eq`). Store join tokens only as hashes.
7. **Secure container defaults:** `no-new-privileges`, no `--privileged`, no host network, no container runtime socket mount, memory/PID limits. Any relaxation must be explicit in the spec.
8. **System images** (HAProxy) are pinned by digest, not by tag.
9. **Authorization** is based on the identity in the client certificate: an agent may only access agent RPCs and data for its own node.
10. Changes touching `pki/`, `secrets/`, the certificates' code (`server/src/certs.rs`, `server/src/acme`), the proxy renderer, or API auth must come with tests for negative cases (malicious input, wrong certificates, expired tokens) and, where relevant, an update to `docs/threat-model.md`.

If a request conflicts with these rules, explain the risk and offer a safe alternative before doing the work.
