# CLAUDE.md

Guidance for Claude Code when working in this repository.

## About the project

Armada is a multi-machine container platform (cloud instances, VMs, or bare metal; do not describe it as VPS-specific). Docs describe Armada on its own terms: do not compare it with or name other products unless a component or protocol really needs naming. Two Go binaries (ADR 0027): `armadad` runs on every machine as root, as `armadad server` (control plane) and `armadad agent` (runs containers through Armada's embedded containerd, ADR 0011), plus the machine commands (`init`, `join`, `doctor`, `backup`, `restore`, `runtime`); `armada` is the client that only talks to the API (no root, Linux and macOS). Ingress uses HAProxy as a system container managed by Armada.

- **Architecture decisions:** `docs/adr/`. **Threat model:** `docs/threat-model.md`

When the design changes, add or update an ADR in the same change. Never let code and documents contradict each other (see "Keeping documents current" below).

## Status

Phases 0–6 are done and tested end to end in local lab VMs (Pebble ACME) and in the cloud: a single server on Oracle Cloud (Oracle Linux 9, SELinux enforcing, Let's Encrypt staging, HTTP-01 and Cloudflare DNS-01 wildcard) three control plane servers on depa.id (leader stop and SIGKILL under load, rolling update through the new leader, all machines rebooted at once), a mixed cluster of those servers (amd64) with the Oracle machine (arm64) as a node, and two depa.id machines on the `wireguard` network mode with the kernel device. Phase 7 (hardening, documentation, release) is in progress: security review fixes, `armadad doctor`, signed release pipeline (GoReleaser + cosign + SBOM + provenance), `install.sh`, `armadad backup`/`restore`, self-healing (ADR 0008), the embedded etcd state store (ADR 0009), the HA control plane (ADR 0010), the embedded container runtime (ADR 0011), quickstart, spec reference and operations guide are done. Roadmap stage 1 (stable for others) is done: rolling upgrades with gated state migrations (ADR 0012), SELinux confinement of containers, replica rebalancing (ADR 0013), the cloud end-to-end test (`test/e2e`), and placement (ADR 0014: node labels, restricted nodes, `placement.require`, image platforms, CPU and memory reservations, `spreadBy`). Armada runs on Linux only, on the embedded runtime. Stage 2 (day-to-day operations) is done: `armada app exec` (ADR 0015), `armada app top` (ADR 0016), the metrics endpoint (ADR 0017), and event history (ADR 0018). Stage 3 is done: jobs and cron (ADR 0019), autoscaling (ADR 0020), scale to zero (ADR 0021), and traffic splitting (ADR 0022). Stage 4 is done: persistent volumes (ADR 0023). Local-first routing in HAProxy (ADR 0024) is done, the first step of the cluster network work before the alpha; the network benchmark (`test/bench`) and the cluster network design (ADR 0025) followed. ADR 0025 is being implemented: nodes get their own container subnet (stage 1a) and route them over a VXLAN tunnel with MTU, firewall, and doctor checks (stage 1b, the `plain` mode), with an encrypted `wireguard` mode and node keys (stage 1c), and replicas publish no ports (stage 2); stage 3 is designed together with spaces (ADR 0026). Spaces, network isolation (the nftables firewall between apps and spaces, isolation from the platform, per-space DNS, the space check in HAProxy's internal frontend, and `ingress.allow`), the log rate limit, and usage per space are done. Stages 1–4 are in the first tagged release, `v0.1.0-alpha.1`. Since then the client and the daemon are separate binaries (ADR 0027), and each person has a certificate of their own that can be removed (ADR 0028), with roles for users and services (ADR 0033); specs take variables and variables from secrets (ADR 0029); machines find and install newer releases themselves (ADR 0030); and the client is `armada NOUN VERB`, with apps and jobs deployed from flags or files and exported as specs (ADR 0032; flat since ADR 0052, step 2); and apps also scale on the length of their queue and on schedules (ADR 0034); and replicas run init containers and sidecars beside the app's container (ADR 0038); and apps take plain TCP from their space inside the cluster (ADR 0039); and jobs also start from a queue, read from a network sandbox (ADR 0040); and volumes back up to an S3-compatible bucket on a schedule, deduplicated and encrypted, and fail over to another node from their latest backup (ADR 0041); and volumes can be NFS exports (ADR 0042); and nodes keep a searchable log history (ADR 0043) and can send app output to Loki or OTLP (ADR 0044); and the leader sends notices about events that need a person to Slack, Discord, Telegram, email, or a webhook (ADR 0045); and nodes run containers without containerd, on the supervisor runtime, the default for new nodes, with containerd kept for nodes set up before (ADR 0046); and an app can bring the DNS token of its custom domains for DNS-01 certificates (ADR 0047); and the client reaches the control plane through an SSH host with no tunnel to keep open (ADR 0048); and machines with only public addresses form a cluster over a WireGuard mesh (ADR 0049); and a running cluster switches between the plain and wireguard modes (ADR 0050, step 1); and a cluster spans sites, with nodes and servers joining from another site over WireGuard between public addresses (ADR 0050, step 2); and nodes behind NAT join with no public address and reach the nodes behind NAT of other sites through a relay (ADR 0050, step 3); and the leader backs the control plane up to an S3-compatible bucket on a schedule, deduplicated and encrypted, and `armadad restore` restores from it (ADR 0051); and secrets belong to a space, as named sets of keys every app of the space can use, the secret named after an app being its own (ADR 0052, step 1); and every command is a noun and a verb, the old words removed (ADR 0052, step 2); and names are discoverable: `app restart`, `replica list` with short replica names, exec with a shell by default, errors that list the choices, and Tab completion from the cluster (ADR 0052, step 3); and every command's help opens with examples (ADR 0052, step 4); and the node's resolver runs as `armada-dns`, a Rust program in a unit of its own that outlives `armadad` restarts (ADR 0053); and the node agent is moving to Rust in steps, as `armada-node` in the runtime pack, the control plane staying in Go (ADR 0054; moving the control plane and etcd is a separate decision, never started without the owner): HAProxy's configuration is rendered by it, and a node opts in to its cluster network with `agent.json` `"netAgent": "rust"` (the default once the lab end-to-end tests pass with it); and supervisor nodes run their containers through armada-node by default (images, root filesystems, bundles, shims, samples, dials, and exec; Go's driver above it; `"runtimeAgent": "go"` opts out), the agent's start converting the node's image store into armada-node's without pulling again and moving every container's root filesystem with no restart, so the old store goes at once, and every node reporting where it stands to `armada cluster status`, `armada node show`, and `armadad doctor` (ADR 0054 step 4); and the leader moves containerd nodes to the supervisor runtime by itself, one at a time, draining each first (ADR 0054 step 4; removing Go's runtime code comes next); and volume archives, restores, and sizes run in armada-node, the agent keeping the session and doing a call itself when armada-node fails before the stream is touched (ADR 0054 step 5, second part; `"volumeAgent": "go"` opts out); and volumes back up to their buckets, and are listed, pruned, and restored from them, through armada-node, in the repository format Go writes and reads (ADR 0054 step 5, third part; the same opt-out); and supervisor nodes read the connection tracking table, mount NFS exports, and read Redis and RabbitMQ queue lengths from containers' network namespaces through armada-node (ADR 0054 step 5, the readings); and exec sessions (the agent's, command probes, queue commands, and system execs) run in armada-node, which starts runc, copies and drains the streams, and answers with the exit code, the agent keeping the gRPC session and the caller's deadline (ADR 0054 step 5, last part); and moving the agent's loop, the control plane, the machine commands, and the client to Rust in one release, with etcd run from the runtime pack as a unit of its own, is accepted (ADR 0055). Do not build features outside the agreed scope unless asked.

Module path: `github.com/ryanbekhen/armada`. The toolchain is pinned with `toolchain` in `go.mod` (a patch release with no govulncheck findings); golangci-lint must be built with the same toolchain.

## Architecture in brief

- **Desired state + reconciliation**: the CLI only writes desired state to the server; reconcilers on the server and agents converge actual state. Every operation goes through this path; never add a "just run the container" path from the CLI.
- Agents open the gRPC (mTLS) connection to the server; the server sends assignments over a bidirectional stream.
- Nodes (ADR 0003): joining goes through a separate join listener (server-only TLS, serves only `JoinService`, rate limited, connections bounded before TLS by `connLimit` (256, 16 per source) and closed after 15 s idle or 2 min; `Config.JoinListener`/`JoinIdle` in tests); the main API is always strict mTLS. The joining node pins the CA by hash without `InsecureSkipVerify`. Node certificates last 30 days, are renewed by the agent, and are only accepted while their serial is recorded in `node_certs` (removing a node revokes them; `RemoveNode` first queues an empty assignment on the node's session, which the send loop flushes before it ends (`flushSession`), so the removed agent stops what it ran). Each server renews its own server and etcd member certificates (`certRenewer`: at start before loading, then every 12h, `pki.RenewDue` = last third or expired) with `CA.Reissue` (same key, one file written atomically); `pki.ServerCert` serves the current one on every handshake (API, join, metrics), and etcd and `clientTLS` read the member files per handshake. Before the embedded agent starts, `certRenewer.renewNode` re-signs the machine's expired node certificate (recorded with `RecordNodeCert` first; a removed node is refused), otherwise the agent, and with it the server, could not start. Admin certificates: `armada admin renew` (`RenewAdminCertificate`, caller's own name, audited) or `armadad admin renew` with the CA on disk; doctor's `certificates` check warns and fails on expiry. Cordoned nodes get no new replicas and are evacuated without dropping below the desired serving count. Unevenly spread apps are rebalanced one replica at a time across the cluster through the same path (ADR 0013). Placement (ADR 0014): admin-only node labels (CLI or join token; `armada.os`/`armada.arch` reported by the agent, `armada.site` from `Node.Site` (ADR 0050: `JoinToken.Site`, `SetNodeSite`, audited, `SiteChanged` event; empty = the first site, no label), `armada.` reserved), restricted nodes, `placement.require`, and `placement.spreadBy` (soft: even over a label's values, then nodes; yields to capacity; only labelled nodes; rebalancing compares values first, then nodes within a value); every scheduling path (scale, rollout, self-healing, evacuation, rebalancing) only picks nodes from `eligible()`, and replicas on nodes that stop being eligible move like cordoned ones. Image platforms are learned from agents after a pull (or from the registry when the image has no variant for the node; `runtime.PlatformError`), kept once per revision like the digest, and restrict `eligible()`; the control plane never contacts registries. Replicas reserve CPU (`resources.cpu`, default 100m, also the limit when set) and memory with no overcommit; `allocatable()` subtracts what Armada keeps (100m CPU and 128Mi per node, 100m more on servers) before `pickNode`, and capacity only fits and breaks ties, never outranks the replica count (T28). `pickNode` also skips a node with its own subnet at `maxSubnetReplicas` (250, `replicasFull`;
finished job attempts hold no address). A replica that has kept failing to start for a minute, outside a rollout, is replaced on another node that fits (`moveFailed`, one per app at a time). A pass works out once what each app needs to know about all the replicas (`reconcileRun.view`, `replicaView`: replicas per app, `placedUse` per node), again only after a change, so its cost does not grow with apps times replicas. `ReplicaSpec.cpu_reserve_millis` sets the container's CPU weight and stays out of the agent's spec hash.
- Internal ingress (ADR 0007): `<app>.internal` is served by a HAProxy `frontend internal` bound to the container bridge gateway (`armada0`) (never the private IP: NAT and load balancers make that reachable from the internet) and resolved by the node's resolver on the same address: `armada-dns` (ADR 0053; `dns/`, Rust std only, in the runtime pack as `embedded.BinDNS`; `dnsserver.Process` runs it with `systemd-run` as `armada-dns-<hash of program and settings>` (`Restart=always`) so it outlives `armadad`, reuses a running unit, and talks to it over `/run/armada/dns/<hash>.sock` (one line per connection: `names`, `clients`, `epoch`, `state`, `drain`), sends everything again to a process with a new epoch (`Process.keep` every 5 s); a new unit reads the old one's state (`--take-over`) before binding with `SO_REUSEPORT`, then the old one drains (its UDP socket connected away, held lookups answered) and stops (`handOver`); UDP is an epoll loop per CPU (≤4, `dns/src/udp.rs`) forwarding each lookup on its own socket; `startInternalDNS` falls back to the in-process `dnsserver.Server` when the pack has no `armada-dns` or it does not start; `runtime reset` stops the units (`dnsserver.StopUnits`)), else the Go `internal/dnsserver` in `armadad`, with the same rules: which answers only the bridge subnet and forwards other names at most 128 at a time, 16 per client address (`maxInflightPerClient`, checked before the node pool), with at most 16 TCP connections per client (`clientListener`). Names alone within a space: the agent gives each container `runtime.ContainerSpec.DNSSearch` = `spec.InternalSearchDomain(app)` (`internal` or `<space>.internal`, checked by `spec.ValidSearchDomain` in `CheckContainerSpec`; outside the spec hash), which the embedded runtime puts first in one merged `search` line (`resolvConf`, at most 6), and the internal frontend completes a `Host` without a dot with the caller's space (`txn.cspace`; `.internal` alone without a clients map). Internal and public rules never mix; the `.internal` zone is reserved.
- Container runtime (ADR 0011, ADR 0046): new nodes run the supervisor (below); nodes set up before run Armada's own containerd, run from binaries pinned in `internal/runtime/embedded/lock.go` and embedded in release builds (build tag `bundle`); `armada-runtime.service` runs `armadad runtime`, which extracts and verifies the pack and execs containerd (own root, socket `/run/armada/containerd/containerd.sock`, namespace `armada`, config format 4 with `imports = []`, no CRI/NRI/TCP/debug/metrics, restart monitor disabled). `internal/runtime/containerd` builds the OCI spec itself (shared checks in `runtime.CheckContainerSpec`), uses CNI (`armada0` with a fixed MAC from `bridgeMAC`, host-local IPAM on tmpfs with a default route, portmap on the private IP, firewall); every address given back (`cniNetwork.Teardown`: Remove, `ReleaseNetwork`, sandboxes) has its host conntrack entries deleted right after CNI DEL (`forgetAddr` → `forgetConnections`, netlink `ConntrackDeleteFilters` on original source/destination and either reply address, address read from the plugins cache first; failure only logged), since isolation accepts established flows first and the address may go to another space next, app containers and their members run at OOM score adjustment 0 (`appOOMScoreAdj`, not their shim's -999) and `armada-server`/`armada-agent` at -500, so the kernel kills workloads before the node's daemon; the AppArmor profile is (re)loaded when the agent starts (`runtime.AgentStarter`, `Driver.AgentStart`; not from `Ping`, which doctor also calls), unique container IDs per creation (`<name>-<hex>`), one runc shim per app and runtime pack on a node (`shimGroup`, annotation `io.containerd.runc.v2.group`), and logs through one process per container that the shim runs: the pack's `armada-log` (`logger/`, Rust, standard library only, under 1 MiB; `Driver.logIO`, `embedded.BinLogger`; `mkbundle -logger` checks its ELF architecture), else `armadad runtime-log` (`embedded.WriteLogs`, the reference `TestArmadaLogMatchesGo` compares against; `armada-log` alone keeps draining after a write error): rotation at `runtime.LogMaxSize`×`LogMaxFiles`, and a token bucket of `LogRate` 1 MiB/s with `LogBurst` 4 MiB per container; excess is dropped, never blocked, and counted in one stderr line when output fits again or at close). `agent.json` records `"runtime": "embedded"` or `"supervisor"` (any other value is refused: remove and rejoin the node). Supervisor runtime (ADR 0046, the default for new nodes (`defaultRuntime`; an agent.json with no runtime stays on containerd), `--runtime embedded|supervisor`, `armadad runtime migrate`; doctor warns on containerd nodes): the driver reaches containers through `backend` (`internal/runtime/containerd/backend.go`: the containerd client, or `supervisor.Store`, which implements containerd's `client.Container`/`Task`/`Process`/`Image`), so everything else in the driver is shared; `internal/runtime/supervisor` keeps images without a daemon (`Images`: containerd's local content store, overlay snapshotter, and layer applier in process, `pullParallel` 2, `images.json`, `Delete` collects unused layers and blobs), OCI bundles (`Bundles`: rootfs mounted from a snapshot prepared before the spec, `config.json`, `record.json` last), and `armada-shim` processes (`Shims`: one per spec group as a transient systemd unit `armada-shim-<hash>` via `systemd-run`, socket `/run/armada/shim/<hash>.sock`; unit limits as `armada-runtime.service` (`LimitNPROC`/`LimitCORE`/`LimitNOFILE`/`TasksMax` infinity, `OOMScoreAdjust=-999`); `For` and `Abandon` hold a per-group lock (`Shims.lock`); `abandon` kills and deletes what a shim left in its runc root only once it is gone (`Shims.gone`: socket ENOENT/ECONNREFUSED, or its unit not active per `Shims.Active`, default `systemctl show ActiveState`), never for a timeout or EOF, so `container.Task` returns the error and the next pass asks again); exec is `runc exec` in the foreground from the agent (pty for `-t`; a SIGKILL, or a `Delete` whose context ends first (`abandon`), metrics are read from cgroup files (`readCgroup`). `armada-shim` (`shim/`, Rust std only, `extern "C"` prctl/waitpid/kill/dup2/fcntl): subreaper, `runc create/start/kill/delete`, `armada-log` on fds 3/4/5, one request line per connection (`create`, `start`, `state`, `wait`, `kill [all]`, `delete`, `list`), exits 10 s after its last container (`IDLE_EXIT`); refuses a pid ≤ 1 from runc's pid file and `runc delete --force`s a container whose pid file fails (`parse_pid`); keeps at most `MAX_EXITS` (4096) unclaimed exit codes, oldest past `EXIT_GRACE` dropped first, containers' pinned (`Exits`). On supervisor nodes the agent installs the pack (`installPack`) and `armadad runtime` exits.
- Admin config (ADR 0027): `armadad init` writes `clientconfig.SystemPath` (`/etc/armada/admin.config`, root:`armada` 0640 via `SaveShared`, `/etc/armada` gets o+x only); `clientconfig.DefaultPath` = `$ARMADA_CONFIG`, else `~/.armada/config` if it exists, else the system path; `Load` accepts group read only for root-owned 0640 group `armada` (`sharedOK`); `Config.SSH` (ADR 0048): every connection runs the user's `ssh -o ExitOnForwardFailure=yes -W ADDR -- DEST` (`sshDialer`, `SSHProgram`, a net.Conn over pipes with deadlines, ssh's last stderr line in errors; `CheckSSH` refuses option-like or shell destinations; the config's servers only, no machine list; tests use the `clientconfig/sshtest` stand-in, which reaches only `bastion.test`); `SaveFile` keeps a shared file shared; the installer creates the group. Run through sudo, init and `server join` add `SUDO_USER` to the group (`joinAdminGroup`, `groupCommand`: `usermod -a -G`, else `gpasswd -a`, else BusyBox `addgroup`, also looked up in the sbin directories; failure only warns; they print to log in again or `newgrp armada`) instead of copying the file to the home, and init names the first user (cluster-admin) after them; each server renews the user certificate in its own shared file (`certRenewer.renewAdmin`, only as root from the default data directory, at start and every 12h once `pki.RenewDue`, new key, signed by the CA and recorded with `RenewedUser`, so a deleted or replaced user stays out; `SaveFile` keeps it shared); an unreadable shared file says whether the account is outside the group or joined after the session started (`groupAdvice`).
- Access control (ADR 0033): principals are users (`pki.KindUser`, one year, `SignUserCSR`) and services (`pki.KindService`, 90 days, `SignServiceCSR`); `Identity.Principal()` reads the old kinds `admin`/`automation` as user/service. `store.Principal` records under `users/` and `services/` (schema 9, `migrateAccess` moves `admins/` and `automation/` without changing rights) hold `Roles []Grant` (role + space, "" = cluster; `CheckGrant`: `cluster-admin`/`space-creator` cluster only, `deployer`/`admin` one space and never `default`, `viewer` either) and allowed node `Labels`. Users: `Since` + `SinceSerial` + `Cutoff` (`principalRec.userAllowed`: the certificate a replacement recorded, by serial, and ones issued (NotBefore + `pki.ClockSkew`) in a later second than the record was written; older records compare NotBefore with `Since`), deleted = tombstone; `RenewOwnCertificate` for users signs, then `RenewedUser` checks the caller and audits in one transaction, rate limited per name (`userRenewLimit`); `UserAccess` gives a name with no record cluster-admin only for a certificate issued (NotBefore + `pki.ClockSkew`) by `meta/user-cutoff` (schema 14, `migrateUsers`, kept when it exists) or while the keyspace is older; a keyspace created at 14 refuses every such name, and `RenewedUser` applies the same check (`etx.unrecordedUserAllowed`), so a user lost in a restore is refused. Everything that signs a user certificate outside the API records the name first with `KnowUser` (cluster-admin unless on record): init, `armadad user renew` (`recordUser`, through `stateClient`), and `armadad server join` (`JoinServerRequest.user_name`, recorded by the leader's `JoinServer`; `joinedClientConfigs` writes nothing without `user_recorded`). Services: recorded serials (`RecordServiceCert`, keep = renewal), `ServiceAccess`. `authorizePrincipal` (`internal/server/auth.go`, `methodAccess`) reads roles on every call, and `streamGuard` (`streamguard.go`, started by `streamAuth` for principals) again every `Config.StreamRecheck` (5s) while a stream is open, also at the certificate's NotAfter: a refusal cancels the stream's context and the stream ends with that error; handlers register their app/node checks with `requireAccess`, Events filters with `streamAccess` (the latest access), and Logs calls `recheckAccess` before following a new replica: cluster-admin calls every `AdminService` method; others only methods in `methodNeeds` (`access.go`: `needView`/`needDeploy`/`needAdmin` space levels, `needCreateSpaces`, `needSelf`; anything missing is cluster-admin only, tested over the whole service descriptor) that a role `reaches`; handlers check spaces through `accessFrom(ctx)` (`app`, `space`, `sees` against the method's level; `creates`; `placement` against the labels; `admin()` = cluster-admin or `internalContext`). RPCs (`rbac.go`, cluster-admin only): `CreateUser`, `IssueUserCertificate`, `CreateService`, `IssueServiceCertificate`, `ListPrincipals`, `UpdatePrincipal`, `DeletePrincipal`, `CreateAssignment`, `DeleteAssignment`, `ListRoles`; `RenewOwnCertificate` for any principal. Nobody deletes themselves or drops their own cluster-admin. `CreateSpace(.., by)` makes a space-creator `admin` of the new space in the same transaction; `DeleteSpace` takes every role in it back (`forgetSpace`); for non-cluster-admins `Events` and history searches leave out what a space's apps left before the space was created (`spacesCreated`, `beforeSpace`), so a recreated name shows nothing of the earlier space. Non-cluster-admins get no nodes and no cluster events.
- Platforms: Armada runs on Linux only (linux/amd64 and linux/arm64 releases); only the `armada` client also builds for macOS (darwin archives, client-only `install.sh`); Linux releases also carry a client-only archive (`armada-client_<version>_linux_<arch>`) that `install.sh` uses with `ARMADA_CLIENT_ONLY=1` (falling back to the full archive for older releases), and a full install puts both binaries as separate files; Windows has no native client, the docs point to the Linux client in WSL 2. Binaries (ADR 0027): `internal/daemon` (`cmd/armadad`) holds every command that runs on a machine; `internal/cli` (`cmd/armada`) only talks to the API and never imports `internal/daemon` or what a machine needs (`TestClientDependencies`); the daemon reuses `cli.Run`, `cli.RPCError`, `cli.ReadSecretValue`, `cli.NewVersionCommand`. Tests that run a server in process and drive client commands live in `internal/daemon` (`execute` sends each command to the binary that has it). Removed `Hello` fields (`runtime`, `min_memory_bytes`) are reserved in the proto.
- Command line (ADR 0032, ADR 0052): `armada NOUN VERB` and nothing deeper; the root holds only nouns and `version`, listed in four groups (Apps, Cluster, Access, Monitoring: `cobra.Group`, `listGroups` in `usage.go`); no old names or aliases beyond `ls`/`rm` and plural nouns, and the words before ADR 0052 fail with `unknown command` (`TestCommandAliases`). `app deploy` and `job deploy` (`internal/cli/appspec.go`: `specFlags`, `runDeploy`: `--new` = `runCreate`, else `runUpdate`, which creates what does not exist) build a `spec.App` from flags (or read `--file`, with `--vars`/`--var`), validate it with `spec.ParseIn` after `Export`, and send `DeployRequest` with `must_create`, or `must_exist` + `base_revision` (the revision `GetAppSpec` returned; flag updates only), so a change in between is refused; `--diff` prints a line diff (`diff.go`) of the exported specs and deploys nothing. `app show`/`job show -o yaml` print `GetAppSpec` as is. `app list` follows `ListApps`' `next_page_token`; `cluster status` is `ClusterStatus`. `Status` with an app (`app show`, rollout waits every second; `appStatus`) returns that app and no nodes, reading its own replicas (`ReplicaFilter{App}`), the node records, and only its own domains (`appURLSource`); every replica and the servers (`allocatable`) only when `placementNeedsCluster` says its placement message compares with them. Other read paths stay in a few batches whatever the cluster's size: `ListVolumes` (`mountedVolumesOf`: `store.GetApps`, then `GetRevisions` for targets), `ListJobs` (runs grouped by job), `ListSpaces` (counts from `store.ListAppIDs`, keys only). The space: `--space`, else `ARMADA_SPACE`, else `clientconfig.Config.Space` (`space use`, checked with `ListSpaces`), else default (`globals.resolveSpace` in the root's `PersistentPreRunE`); `-A` spans spaces in lists. Output: lists print a table only, actions one line of what happened, `-o json` (protojson) on everything that prints data (`outputFlag`); `dialAdmin` is a variable so tests drive commands against a fake client. `explain` (`usage.go`, run by `Run` on both trees) replaces cobra's argument errors with the missing placeholders of the Use line (or how many are too many; never an argument's value, which may be a secret) plus the usage line, points flag errors to `--help`, and lists each verb with its arguments in a noun's help. `replica list` (`replicas.go`) reads `Status`; `app exec` runs `defaultShell` without a command and sets `-i`/`-t` from the terminal unless given. The switch probe is armada-node's `net probe` run beside the agent like Go's: `net apply` marks the switch state `probing` and answers `probe` (from and peers' tunnel addresses), `startProbe` runs it in a goroutine in the caller's network namespace (Go's `ping` when the program does not answer), records `reached`/`probed`, and clears `probing` `probeEvery` after the start. `node/src/net/diagnose.rs` is Diagnose (Go's names, levels, and details, netlink errors worded as Go's libraries word them; a device only the userspace socket holds answers `needsUserspace`).
- HAProxy: structural changes (new app/domain/route) = re-render + `haproxy -c` + reload (`Driver.reload`: SIGUSR2, then waits until `show info` names a new process, at most `reloadWait` 10s, so live changes after it reach the new process; a timeout makes the next Apply reload again); deploy/scale/drain/certificates = Runtime API over a Unix socket (`set ssl cert` payloads go through `pemPayload`, which drops the empty lines issued bundles have between blocks; a live certificate update that still fails reloads HAProxy, which reads the new file). Do not use the Data Plane API. Long-lived connections: `timeout tunnel 1h`,
`hard-stop-after 1h`; `ingress.timeout` → `proxy.Backend.TimeoutSeconds` renders `timeout server` in the app's backend. A new agent takes over a running proxy with no reload when the configuration differs only in server lines (`liveConfig`, `sameStructure`; slots from `show servers state`, the same certificate names). Local-first routing (ADR 0024): `proxy.Backend.LocalFirst` (`ProxyBackend.local_first`, set by `buildProxy` unless the app splits traffic) makes `be_<app>` `balance leastconn` with each server weighing `localWeight` (11) on the node's private IP or in its container subnet and `remoteWeight` (10) otherwise (`backendPool`), set through the Runtime API like an address. Idle servers tie, so the backend's own `use-server` rule picks a local slot from `local.map` (`localMap`, `replaceMap`) while `be_conn` is at most 1, for requests from the internal frontends only (`!{ fe_name http } !{ fe_name https }`, `frontendHTTP`/`frontendHTTPS`): public requests arrive at one node often and would all stay on it at low load, so they balance over every replica. Nothing about local-first reloads the proxy or adds a frontend rule; every `http-request` rule is written before the `use_backend` rules. A rule that matches a whole host with no `ingress.allow` and no wake needs no rules of its own (`mapped`): `routeMap` writes it to `routes-<frontend>-<hash>.map` (0600, named after its content, `<space>/<host>` keys on the internal frontend so another space's caller finds no route), and `use_backend %[var(txn.route)]` picks its backend, so a request's cost does not grow with the apps of the cluster. `Layout` is keyed by HAProxy backend name; `parseLoad` reads `be_` rows. `Driver.Load` keeps `ServerLoad.Total` growing across reloads: `Apply` reads it just before a reload, and when `show info` names another process the latest totals carry over.
- Rollouts (ADR 0005): an app has an `active_revision` (serving) and a `target_revision` (rolling out). Agents decide readiness through probes, HTTP or a `command` run like `armada app exec` (`checkCommand`; output dropped, arguments never logged) (a container older than the agent stays out of reports until a first verdict, `awaitsVerdict`; the implicit port check slows to about 10 seconds once ready, `implicitPeriod`); the server only puts `running` + `ready` replicas in the proxy, retires old replicas after the warm-up, and deletes them after the drain timeout (`drain` in the spec, default 10s, `drainFor`), counted from the later of `DrainingSince` and the leader's `termStart`, and held up to `awayHold` (1m) more while a node is away (`reconcileRun.away`: disconnected, not lost), except for apps with volumes (`finishDrain`'s hold). Never delete a replica that serves traffic without draining it. The agent applies the proxy before removing containers it no longer wants (`Reconcile`, strays), reconnects every `failoverRetry` (1s, jittered) for `failoverWindow` (2m) after a session it had ends (`reconnectWait`), gives up on a session the server does not answer within `sessionAnswer` (10s), and the gRPC channel's backoff is capped at 1s (`clientconfig.Dial`).
- Removing an app: `RemoveApp` sets `appRec.Removing` (`MarkAppRemoving`, audited; refused for jobs); the leader's `reconcileRemoval` retires its replicas through the normal drain and calls `DeleteApp` (revisions and secrets, in one transaction, only with no replicas left). Deploy refuses a name being removed. Volumes stay, so `armada volume delete` works with the app gone, and a space holding them cannot be deleted until then.
- Secrets (ADR 0006, ADR 0052): a secret belongs to a space and holds keys; it is named by an ID like an app's (`spec.AppID`), and the secret with an app's ID is that app's own, so the layout of before is unchanged: `secrets/<ID>/<key>/<version>`, `secretseq/<ID>/<key>`, and the RPCs `SetSecret`/`ListSecrets`/`DeleteSecret` (their `app` field is the secret's ID, `name` the key; `DeleteSecret.whole` deletes every key), plus `ListSpaceSecrets`. A spec reference (`spec.ValidateSecretRef`) is `KEY` (the app's own secret) or `SECRET/KEY` (`spec.SecretSource` resolves it within the app's space; another space is never reachable); keys are `spec.ValidateSecretKey` (a secret name or a variable name). Revisions pin each reference as written (`rev.Secrets["db/url"]`), and `Deploy` records the app under `secretusers/<secret ID>/<app ID>` (`noteSecretUsers`) for every other secret it pins, so `secretPins` (pruning, `servingPins` for deletes and `ListSpaceSecrets`, `ListSecrets` used-by, `SetSecret` rollouts of every app whose target revision uses the key, `checkSecretBackups`); `RestartApp` (`Etcd.RestartApp`, `deployRevision` with force: a new revision of the target spec with the latest versions even when nothing changed; refuses jobs, traffic splits, apps being removed; the server runs `checkStoredRevision` and `checkBackupTargets` with the latest values first, audits `app.restart`, records `Restarted`) reads only those apps' revisions and drops entries of apps that pin none any more; `DeleteApp` keeps the app's secret while another app pins it. Deploying a spec that `UsesSpaceSecrets` needs schema 15 (`needSchema`: every server upgraded), since an older leader would read `SECRET/KEY` as a key of the app's own secret; `TestLegacySecretsAssignmentUnchanged` compares a replica's spec with one written by the release before (`testdata/legacy-secrets.golden`). Values are encrypted with `internal/secrets` (envelope AES-256-GCM, master key `master.key`, the secret's ID and key as scope and name). The server decrypts only while building a node's assignment, and keeps the versions it opened in memory across passes (`openedSecrets`, dropped once no pass uses them, `forget` on DeleteSecret; never in etcd or logs); versions are never reused (`secretseq/<app>/<name>` keeps a deleted secret's last version), and done or draining replicas whose pinned version is gone get `unresolvedSecrets` (the reference only); the agent writes secret files only to its tmpfs secrets directory. Never log `ReplicaSpec`, `Assignment`, or `SetSecretRequest` (protobuf-go ignores `debug_redact`), and never put secret values in container labels or the spec hash.
- Armada's containers and resources are identified by `armada.*` labels and must be idempotent: an agent can restart at any time and adopt existing containers. `armada-server.service` already runs the node's agent; `runAgent` holds an exclusive `flock` on the data directory (`lockDataDir`), so a second agent on a node is refused.
- State lives in etcd embedded in `armadad server` (ADR 0009; `internal/etcd` runs the member, `store.Etcd` implements `store.Store`): JSON records under `/armada/`, optimistic serializable transactions (`Etcd.tx`; the callback may run more than once, so no side effects outside it). etcd accepts only TLS 1.3 client certificates with the shared `etcd:member` identity (the Armada API refuses it) and listens on the server's private IP, never publicly; the member certificate names every private address of the machine (do not skip etcd's client SAN check). Transactions delete many keys by range (`etx.deleteRange`/`deletePrefix`, one operation each; no write into a deleted range in the same transaction): `DeleteApp`, `DeleteJob`, and the audit trim; etcd allows `maxTxnOps` (4096) operations per transaction (`internal/etcd`); tests see each commit's operation count through `Etcd.onCommit`. A transaction reads one app's replicas by key prefix (`appReplicas`: deploys, revision pruning, `ListReplicas` with an app, app and job removal, job runs): replica IDs start with `<app>-` (`replicaPrefix`, enforced by `CreateReplica`), and the record's app still decides, since `web-` also holds `web-api`'s; tests see each list's key count through `Etcd.onList`. Domain claims and pruning still read every live spec (`liveSpecs`): a domain record names its space, not the apps that route it. A reconcile pass logs an app it cannot reconcile, records `ReconcileFailed` once (a condition), and goes on with the others; only `ErrNotLeader` or a cancelled context end the pass. `SetNodeStatus` writes nothing when only a LastSeen less than `nodeSeenEvery` (30s) newer changed, so agent reports do not move the commit key under every other transaction. Incompatible record changes bump `etcdSchema` with a migration; a binary refuses a newer schema. Tests use a shared embedded member per package (`store/storetest`, `TestMain`). Reads of many revisions go through `getMany` (`GetRevisions`, `revisionCache.preload`, `ListApps`, `liveSpecs`): read-only transactions of `readBatch` gets at the snapshot revision. Do not add dependencies that need CGO. A new file in the data directory must be added to `internal/backup` (a test checks the layout).
- Control plane topology (ADR 0010): one server is supported, three are recommended. Servers elect a leader through etcd (`etcd.Campaign`); only the leader serves the API/join listener and runs reconcilers and certmagic, each term with a fresh `server.Server` and a store fenced on the election key (`Etcd.Fenced`, `ErrNotLeader`). Servers join with a single-use server token (`token create --server`, `server join`), which hands over the CA and master keys; new members start as etcd learners and are promoted by the leader. Agents and the CLI hold every server address and dial with `pick_first`. The leader puts the API addresses of its last pass (`Server.endpointsSeen`) in the `armada-servers` header (`clientconfig.ServersHeader`) of every AdminService answer; `cli.serverSync` writes a different set back to the client config once per run (silently, `SaveFile`; a shared config only as root; a config with a loopback address no server has, an SSH tunnel, is kept: `tunnelled`). An agent run as root from the default data directory writes its server list to `clientconfig.ServersPath` (`/etc/armada/servers`, 0644, its directory given o+x explicitly since the units' umask is 0077, `writeMachineServers` at start and on every change), and `Config.Dial` appends its addresses the config lacks (`MachineServers`: root-owned, not group/other-writable, ≤64 KiB, private addresses only). `armadad server join` run as root writes `/etc/armada/admin.config` like init (`joinedClientConfigs`: user certificate for `--user-name`/the sudo user signed with the received CA; an existing file kept; failure only warns) and adds the sudo user to the group. ACME data lives in etcd (`certs.EtcdStorage`, `/armada-acme/`).

## Code conventions

- Everything is in **English**: code, identifiers, comments, commit messages, error messages, and all documentation (open source project for a global audience).
- Licenses (mandatory): Armada is Apache-2.0 and must stay free for commercial use. New Go modules only under Apache-2.0, MIT, BSD-2-Clause, BSD-3-Clause, ISC, MPL-2.0, or CC0-1.0 (`make licenses`, CI); `armada-log` (`logger/`), `armada-shim`, and `armada-dns` use the Rust standard library only (`TestLoggerStandardLibraryOnly`), and the notices name the libraries they link statically (Rust std, musl); `armada-node` (`node/`, ADR 0054) may use crates under the same licenses plus Unicode-3.0 (Unicode data), checked from `Cargo.lock` in CI and listed in `THIRD_PARTY_NOTICES.md`; never GPL, AGPL, SSPL, BUSL, or anything that limits commercial use, and no copied code under such licenses. Do not change MPL-2.0 files of a dependency. Changing an embedded runtime program (`lock.go`) updates `THIRD_PARTY_NOTICES.md` in the same change (`TestNoticesMatchLock`); its static LGPL libraries (glibc, libseccomp) are listed there with their source. Release archives carry `LICENSE`, `THIRD_PARTY_NOTICES.md`, `third_party/licenses/`, and `licenses/go/`. Images Armada pulls at run time (HAProxy, GPL-2.0) run as separate containers and are never linked or bundled.
- Commit subjects follow Conventional Commits, `type(scope)!: description`, because the release notes are grouped by type (`.goreleaser.yaml`) and CI rejects other subjects (`scripts/check-commits.sh`). Types: `feat`, `fix`, `security`, `perf`, `docs`, `deps`, then `refactor`, `test`, `ci`, `build`, `chore`, `style`, `revert`; `!` marks a breaking change. Write the description for the people reading the release notes. `main` only changes through pull requests that pass every CI job (repository ruleset; see docs/releasing.md).
- Idiomatic Go: `context.Context` as the first argument for I/O, errors wrapped with `fmt.Errorf("...: %w", err)`, logging with `log/slog`.
- All code lives in `internal/` except the protobuf definitions in `api/` (Armada has no public Go API).
- Every runnable command of both binaries has two to four examples a person can copy (`Example`, or the `examples` map in `internal/cli/examples.go` / `internal/daemon/examples.go`); help prints usage, examples, description, flags (`writeHelp`). `cli.ExampleProblems` (run by `TestEveryCommandHasExamples` in both packages) parses every example line that runs the binary against a fresh tree.
- YAML specs are parsed strictly (unknown field = error). Features whose types exist but are not implemented yet must be rejected with a clear message, never silently ignored.
- Tests live next to the code (`_test.go`). Reconciler logic is tested with fake drivers/stores, not a real runtime. HAProxy renderer changes require golden files.
- Development and CI always use ACME staging or Pebble, never the Let's Encrypt production endpoint.

## Keeping documents current (mandatory)

Every change updates, in the same commit or pull request, every document it makes stale. A change is not done until its documents are; do not leave it for a follow-up. Before committing, check at least:

- `README.md`: the short feature table and the document links; `docs/features.md` (full feature list) and `docs/tested-environments.md`.
- `docs/cli/`: run `make docs` whenever a command, flag, or help text changes (generated; never edit by hand).
- `docs/guides/`: the guides that use the changed feature (task recipes; every command and spec in them must stay valid), `docs/concepts.md` for changes to the core ideas, and `docs/README.md` (the documentation home) for new pages.
- `CLAUDE.md`: Status, Commands, Architecture in brief, and these conventions.
- `docs/compatibility.md`: what is stable and what is deprecated; a change to anything it calls stable needs a deprecation there first.
- `docs/`: quickstart, operations guide, spec reference, `threat-model.md` for anything that changes the attack surface or a mitigation, and `docs/adr/` for design decisions (a new ADR, or an update to the one the change supersedes, plus the index in `docs/adr/README.md`).
- CLI help text and error messages that describe the changed behaviour.

## Security rules (mandatory)

This is infrastructure software that holds root on every node. Treat these rules as merge requirements, not suggestions:

1. **Never weaken mTLS** (no `InsecureSkipVerify`, no `--insecure` flag, no plaintext fallback), including for development or tests.
2. **User input into the HAProxy configuration** (domains, paths, app names) must pass whitelist validation in `internal/spec` and be validated again in the renderer. Never interpolate user strings into templates without validation, and never turn them into regular expressions.
3. **Secrets:** never print plaintext to logs, errors, CLI output, or the audit log. Secret types must redact themselves through `String()`/`LogValue()`. Never accept secret values as CLI arguments (they end up in shell history); read them from stdin or a file.
4. **Bind interfaces:** agent/server gRPC, internal DNS, HAProxy stats, and container ports bind only to private IPs. Only HAProxy on ports 80/443 faces the public; in a mesh cluster (ADR 0049) also the WireGuard port, and the leader's join listener only while a join token is open (T90); in a cluster with more than one site (ADR 0050) also the WireGuard port, and the leader's join listener on its endpoint only while a token for another site is open. Never bind internal services to `0.0.0.0`.
5. **Sensitive files** (CA key, master key, TLS private keys, `~/.armada/config`, state DB) are created with `0600`/`0700` permissions. Check permissions when reading them.
6. **Cryptography:** use Go's standard `crypto/*` packages and `crypto/rand`. Never invent cryptographic schemes. Compare tokens with `subtle.ConstantTimeCompare`. Store join tokens only as hashes.
7. **Secure container defaults:** `no-new-privileges`, no `--privileged`, no host network, no container runtime socket mount, memory/PID limits. Any relaxation must be explicit in the spec.
8. **System images** (HAProxy) are pinned by digest, not by tag.
9. **Authorization** is based on the identity in the client certificate: an agent may only access agent RPCs and data for its own node.
10. Changes touching `internal/pki`, `internal/secrets`, `internal/certs`, the proxy renderer, or API auth must come with tests for negative cases (malicious input, wrong certificates, expired tokens) and, where relevant, an update to `docs/threat-model.md`.

If a request conflicts with these rules, explain the risk and offer a safe alternative before doing the work.
