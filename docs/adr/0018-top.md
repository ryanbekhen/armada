# 0018. Resource usage of replicas

- Status: Accepted
- Date: 2026-11-03

## Context

Replicas reserve CPU and memory (ADR 0014), but nothing shows what they
actually use. An operator sizing `resources`, looking for the replica that
is close to its memory limit, or checking how busy a node is has to log in
to each node and read the runtime's own numbers.

The same numbers are what later features need: a metrics endpoint, and
autoscaling, which decides from recent usage rather than from a request
made at that moment. Collecting them once, the same way for every runtime,
serves all of these.

## Decision

`armada top` shows the CPU and memory replicas use:

```
armada top              # per app: replicas measured, CPU used/reserved, memory used/limit
armada top web          # per replica of web: node, state, CPU, memory
armada top --nodes      # per node: what its replicas use and reserve, and what it can give
```

It prints once; `-o json` gives the full response. A replica without a
recent sample shows `-`.

### Sampling

- Every agent samples its running replica containers every 10 seconds:
  the cumulative CPU time and the memory in use without page cache the
  kernel can reclaim (for cgroup v2, usage less inactive file pages), which
  is what counts toward the memory limit before the kernel kills anything.
- CPU is reported as millicores over the interval, so a replica appears
  from its second sample on. A new container, or a counter that goes
  backwards, starts over.
- The agent sends a `UsageReport` on its control stream, apart from the
  replica report: usage changes on every sample, while replica reports are
  sent only when they change and are written to the store. The same report
  carries the requests in progress at the node's proxy, which the
  autoscaler reads (ADR 0022).

### Server

- The leader keeps the latest sample of each node in memory only, never in
  etcd. Losing it costs nothing: a new leader has samples again after one
  interval, and a node that disconnects is dropped at once.
- A sample counts for 35 seconds. A replica's usage counts only when it
  comes from the node the replica is assigned to, which is checked when the
  sample is read, so a report costs no store access. Values are bounded,
  and a report with more than 1024 replicas is dropped.
- `AdminService.Top` joins the samples with the replicas, their
  reservations and limits, and each node's allocatable capacity (ADR 0014).
  It needs an admin certificate, like every admin RPC.

### Runtime and drivers

- `runtime.StatsReader` is optional. The embedded runtime reads the task's
  cgroup v2 metrics from containerd.
- The driver protocol adds `Stats` and `CAPABILITY_STATS`; drivers
  implement `driverkit.StatsReader`. The conformance suite runs a container
  that holds 16 MiB and keeps a CPU busy, and checks that the memory is
  between 12 MiB and the limit and that CPU time grows.
- A node whose runtime cannot measure containers sends no usage; its
  replicas show `-`, and nothing else changes.

## Alternatives considered

- **Asking the nodes when the command runs**, like `armada logs`: always
  current, but every call fans out to every node, and the numbers would not
  be there for autoscaling or a metrics endpoint.
- **Usage in the replica report**: one message fewer, but the report would
  change on every sample and be written to etcd every 10 seconds for every
  node.
- **Keeping samples in etcd**: survives a leader change, at the cost of a
  write per node every interval for numbers that are stale within seconds.
- **Usage of the whole machine**: useful, but it is not what replicas
  reserve or what the scheduler decides from; it can be added later.

## Consequences

- The numbers are as old as the last sample, up to 10 seconds, and absent
  for 10 to 20 seconds after a replica or the leader starts.
- There is no history; the metrics endpoint is where history belongs.
- External drivers need an update to report usage; until then their
  replicas show `-`.
- Agents send one small message every 10 seconds, and the leader keeps one
  sample per node in memory.
