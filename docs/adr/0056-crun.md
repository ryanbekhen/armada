# 0056. crun runs the containers

- Status: Accepted; runc left the runtime pack in the release after v0.1.0-alpha.44 (below)
- Date: 2026-11-26 (runc's removal: 2026-11-27)

## Context

The supervisor runtime (ADR 0046) creates, starts, signals, and deletes
containers, and runs commands in them, through an OCI runtime: until now
runc, which the runtime pack carries (`pack/lock.json`). `armada-shim`
runs `runc create`, `start`, `kill --all`, and `delete --force` for the
containers of its app; `armada-node runtime exec` runs `runc exec`
for exec sessions, command probes, queue commands, and system containers'
commands; the agent runs `runc list` and `runc delete --force` to end the
containers of a shim that is gone. Everything else (the OCI spec with its
seccomp profile, AppArmor profile, SELinux labels, cgroup, and
namespaces; the root filesystem; the network; logs) is Armada's own and
does not depend on which runtime reads the spec.

runc is a Go program of about 10 MiB per architecture. It starts as a
process of its own for every one of these calls (a few per container
start, one per probe command, one per exec), and while a container is
created it also runs as the container's first process (`runc init`) until
the container starts.

crun is an OCI runtime written in C, under the GNU General Public License
2.0 or later (its library, libcrun, under the LGPL 2.1 or later). Its
static release program is about 2 MiB per architecture.

## Decision

crun runs every container Armada creates from this release on. The
owner chose it: a much smaller program than runc, quicker to start, with
less memory per call, and no Go runtime in a program that starts this
often.

### The program

The pack carries crun 1.31's own static release build, unchanged, pinned
by SHA-256 like every other program: `crun-1.31-linux-amd64-disable-systemd`
and `crun-1.31-linux-arm64-disable-systemd` from crun's GitHub release
(checked against the release's `CHECKSUMS`). The variant without systemd
support is the right one: Armada gives every container a cgroup path of
its own under `/armada` (`linux.cgroupsPath` = `/armada/<container ID>`,
`node/src/runtime/oci.rs`) and never asks for the systemd cgroup driver
(no `--systemd-cgroup`), so the runtime writes the cgroup itself, and the
shim is already a systemd unit of its own. That variant also links no
libsystemd and is about 40% smaller.

### The license policy

Until now no GPL program was part of what Armada ships. That changes for
a program that runs only as a process of its own:

- A program under the GPL may be in the runtime pack when Armada's
  programs only run it as a separate process (command line, files, pipes),
  never link it or any of its code, and the release carries its complete
  corresponding source and its license.
- Linking GPL code into Armada's own programs stays forbidden, and so does
  code under the AGPL, the SSPL, the BUSL, or any license that limits
  commercial use, anywhere. Armada stays Apache-2.0: anyone may use it
  commercially and run it as a service.

How Armada complies for crun (GPL 2.0, section 3(a): the executable
accompanied by the complete corresponding machine-readable source):

- Every release carries one asset beside its archives, the same for both
  architectures, `armada_<version>_runtime-sources.tar.gz` (GPL 2.0
  section 3: the source offered from the same place as the programs).
  Under `source/runtime/` it holds `crun-1.31/crun-1.31.tar.gz` (crun's
  release source tarball), `crun-1.31/build/` (`flake.nix`, `flake.lock`,
  `nix/derivation.nix`, `nix/static.nix` of crun's tag 1.31: the scripts
  its static programs are built with, which pin the nixpkgs revision that
  builds each library they link), and `libs/<library>-<version>/`: the
  source of every library linked into the pack's static programs as
  their builds used it (for crun glibc, libseccomp, libcap, json-c, and
  on amd64 CRIU for libcriu and protobuf-c, as that nixpkgs revision
  fetches them, with the patches nixpkgs applies and its expressions;
  for tini, which links glibc, the Ubuntu source packages its build
  installed), with `SOURCES.txt`
  naming each file's SHA-256 and address. libgcc's source is not carried:
  the GCC Runtime Library Exception waives it. `checksums.txt` lists the
  asset, so cosign's signature covers it. The full Linux archives carry
  `licenses/runtime/SOURCES.txt` instead, naming the asset and its files,
  so installs and upgrades never download the sources. `pack/lock.json`
  pins each file by SHA-256 (`sources` for crun's own, `libraries` for
  the libraries the programs name in `linked`), and `armada-pack sources`
  (`make runtime-sources`) collects them when a release is built;
  `scripts/release-contents.sh` checks the asset against the pins and
  `checksums.txt`, and that the archives carry no source.
- `licenses/runtime/crun@1.31/` holds crun's `COPYING` (GPL 2.0) and
  `COPYING.libcrun` (LGPL 2.1), taken from that tarball; the repository
  keeps the GPL 2.0 text as `third_party/licenses/GPL-2.0.txt`.
- `THIRD_PARTY_NOTICES.md` names crun with its license, and every library
  the pack's static programs link with theirs and its version (crun:
  glibc, libgcc, libseccomp, libcap, json-c, and on amd64 libcriu and
  protobuf-c; tini: glibc, libgcc).
- `armada-pack`'s tests refuse a pinned program under the GPL without a
  pinned source tarball and license texts, a library a program links
  without a source tarball or a `noSource` that names a license exception
  of the library's license, and AGPL, SSPL, and BUSL licenses in the
  pins.

The client-only archives (Linux and macOS) carry no pack and no crun.

### The transition (v0.1.0-alpha.44)

crun cannot manage the containers runc created (each keeps its own state
in a format of its own), and an upgrade must not restart running
containers. So both stay for a while:

- A new container is created with crun, and its bundle record
  (`record.json`) says so: `"runtime": "crun"`. A record without the field
  is a container runc created (every record written before this release).
- Every later call for a container goes to the runtime that created it:
  start, signals, `kill --all`, delete, exec sessions, probe and queue
  commands, and the cleanup of a shim that is gone
  (`node/src/runtime/container/oci.rs`).
- Each runtime keeps its state in a directory of its own under the
  shim's state: `/run/armada/shim/<shim>/crun` beside
  `/run/armada/shim/<shim>/runc`, so the two never share a `--root`.
- `armada-shim` takes crun as a last, optional argument
  (`serve SOCKET STATE-DIR RUNC ARMADA-LOG [CRUN]`) and a runtime word on
  `create` (`create ID BUNDLE LOGDIR crun`; none is runc, as an older agent
  asks); it remembers each container's runtime for start, `kill --all`,
  and delete. A shim keeps running across an upgrade, and a shim of the
  release before (started without crun) keeps its runc containers: a new
  container of an app goes to a shim of the new pack, since the shim's
  group names the pack.
- When a shim is gone, its containers are ended in both runtimes' state
  directories, each with its own program.
- Containers move to crun as they are recreated: a deploy, a rollout, a
  restart (`armada app restart`), a crash, or a node's restart; and the
  agent recreates the others itself (below), so runc can leave the pack in
  the next release (`docs/compatibility.md` says so first).

### Moving the containers runc created (v0.1.0-alpha.44)

Waiting for every container to be recreated by itself would keep runc in
the pack indefinitely: a replica of an app that is never deployed again
stays on runc, and HAProxy's system container is created again only when
its image changes. So the agent moves them (decided 2026-11-26, a visible
change on the way to the beta), keeping apps serving where it can
(`agent/src/crunmove.rs`):

- The runtime tells the agent which runtime created each container
  (`runtime::Container.oci_runtime`, from the bundle record; a replica
  counts as runc's when its container or one of its init containers or
  sidecars is).
- One replica at a time per node. The agent first reports it starting
  with no address while its runc container still runs, so the leader
  takes it out of every node's proxy; 5 seconds later (`DRAIN`) it stops
  the container with the usual grace and starts the replica again on
  crun, as for a new spec. The restart note says why ("its container
  moved from runc to crun"), so `armada app show` and the restart counts
  show it.
- The next replica waits until the moved one is ready again, for at most
  5 minutes (`READY_WAIT`); a replica that was not ready before its move
  is not waited for. A move whose replica does not get ready again
  holds the next ones back 10 minutes, doubling up to 2 hours
  (`BACKOFF`, `MAX_BACKOFF`), so a node never recreates its replicas one
  after the other into a failure. The same wait applies to any replica
  started on crun in the last 5 minutes and not ready yet, so an agent
  restarted in the middle of a move waits for the replica it moved.
- A replica that is the only server its app's backends list in the
  node's proxy configuration waits 2 minutes (`ALONE_WAIT`) first: the
  app's other replica may be the one another node is moving at that
  moment. An app with replicas on several nodes therefore keeps serving;
  an app with one replica, a volume app among them (recreated in place on
  its node, its volume kept), has a gap of about its start and readiness
  time, as for any restart.
- The agent moves nothing while it has no session with the control plane
  (the leader would not hear of it), while the node moves to another
  runtime, and for replicas that are held (ADR 0023), fenced (ADR 0041),
  paused for a volume operation, crashed (the crash path recreates them,
  on crun), or about to be recreated for a new spec or a probe.
- Job attempts are not recreated: an attempt runs once, so one still
  running ends on runc. Finished attempts hold no process; they stay for
  their logs and are removed with the job's history (24 hours), as
  before, through runc.
- HAProxy last: once no replica of the node is left to move and none is
  being moved, the agent asks the proxy's driver to move. HAProxy binds
  its listeners with `SO_REUSEPORT`, so the engine starts a new HAProxy
  on crun from the configuration on disk beside the old one, both
  listening; once the new one stays up, the old one gets SIGUSR1 (a soft
  stop: it stops listening and finishes its connections) and is stopped
  after 30 seconds (`RETIRE_WAIT`) at the latest; the driver then reloads
  the new one, so the Runtime API socket is surely its own. No request
  waits for a start; a connection accepted by the old HAProxy at the
  moment it stops listening, or one still open after 30 seconds
  (WebSockets), is cut. When the new HAProxy does not stay up beside the
  old one, the old one is stopped first and HAProxy is started again, as
  for any start (a gap of a few seconds); a failure is tried again after
  the same backoff. HAProxy is the only system container.
- The agent logs `moving replicas from runc to crun, one at a time` with
  the count, then `moving replica to crun`, `recreating replica on
  crun`, and `moved replica to crun` for each, `every replica on the
  node runs on crun`, and `moving the proxy to crun` / `moved the proxy
  to crun`. The node reports how many containers runc created are left
  (`RuntimeStatus.runc_containers`, a new field; `armada node show`
  prints it on the Runtime line), and `armadad doctor` warns with the
  count (check `runc`).

### runc leaves the pack

The release after v0.1.0-alpha.44 (which accepts upgrades from it alone)
carries crun and no runc (decided 2026-11-27). Everything that pinned,
packed, extracted, checked, or licensed runc goes with it: its pin in
`pack/lock.json` and the libraries only it linked (Debian's glibc and
GCC, and runc's build scripts for libseccomp, whose tarball crun links
too), its rows in `THIRD_PARTY_NOTICES.md`, `armadad runtime --bin-dir`'s
need for it, and the doctor check and status that counted its
containers (`RuntimeStatus` is gone; its fields are reserved). crun is
the only OCI runtime: `armada-shim serve SOCKET STATE-DIR CRUN
ARMADA-LOG`, every create names crun, and exec sessions, probe and queue
commands, and system execs run `crun exec` with a console socket for a
terminal.

The notes of that release ask for alpha.44's move to finish first (no
`runc` warning from `armadad doctor` on any node). A node upgraded
before then still has containers runc created, which nothing can stop,
signal as a whole, delete, or run a command in through a runtime any
more. So the agent ends them without runc, in every pass, the first at
its start included (`agent/src/runcleft.rs`, `agent/src/supervisor`,
`node/src/runtime/container/cgroup.rs`):

- A container is runc's when its bundle record names runc or no runtime
  (`OciRuntime::of_record`); a replica is, when its container or one of
  its init containers and sidecars is (`Container::on_runc`). Nothing
  else is touched: only containers Armada made have records.
- Ending one: every process in its cgroup killed. The cgroup is the
  spec's `linux.cgroupsPath` (else `/armada/<container ID>`, Armada's own
  path; any path outside `/armada/` is refused), a cgroupfs path in the
  cgroup v2 hierarchy: `cgroup.kill` is written where the kernel has it,
  every process listed in `cgroup.procs` of the cgroup and the cgroups
  below it gets SIGKILL each round (all an older kernel offers), until
  none is left (10 seconds at most), then the cgroups are removed,
  deepest first. A stop with a grace first sends SIGTERM through the
  shim, which signals the process itself.
- Removing one: ended as above, its shim asked to forget it (a shim of
  alpha.44 then runs `runc delete`, which fails as runc is gone, and keeps
  it; once no container of its group is left the agent stops that shim's
  unit, so it does not linger), runc's state of it
  (`/run/armada/shim/<shim>/runc/<ID>`) removed, then its network,
  bundle (unmounted), root filesystem, files, and logs as for any
  container. A gone shim's containers are ended the same way: crun's
  with crun, and each container runc's state names through its cgroup,
  its state removed.
- A replica on runc is ended at once (no grace: no runtime can wait for
  it) and created again on crun in the same pass, reported starting with
  its old container and no address meanwhile, as after a crash, so the
  leader takes it out of every proxy. Its restart note says why ("its
  container was created by runc, which this release does not carry;
  recreated on crun"), and the agent logs `ended a container runc
  created; recreating it on crun` once per container. A job attempt
  still running is left to end by itself (it needs nothing from runc
  while it runs, and an attempt runs once); its removal later goes the
  same way.
- HAProxy's container is replaced as alpha.44 replaced it (a new one on
  crun beside the old, SIGUSR1 to the old one, stopped after 30
  seconds), now at once rather than after the replicas, in the
  background, a failure tried again after 10 minutes doubling up to 2
  hours. Until then the old HAProxy keeps serving, though configuration
  changes that need a check (`haproxy -c` through exec) wait for the new
  one.
- `armada app exec` and command probes refuse such a container with a
  text that says the agent creates it again on crun.

No event or status reports this: the recovery happens at most once per
container, on nodes whose move did not finish, and the restart note in
`armada app show`, the restart counts, and the agent's log show it. A
count to watch would stay at zero on every node that followed the notes.

Old packs and shims: installing a pack removes the other packs'
directories, as before. Nothing runs from a pack's own directory: the
agent names every program, and the shims it starts with them, through
`/var/lib/armada/runtime/current/bin`, so a shim started from alpha.44's
pack runs the installed pack's crun and armada-log once `current` moves
(the same crun 1.31), and its containers (tini is bind-mounted into each
from the pack it was created with, which the mount keeps) run on. A shim
of alpha.44 keeps serving its crun containers with the new pack's crun,
and its runc containers only until they are ended as above.

### What stays the same

The OCI spec Armada writes (seccomp, AppArmor, SELinux labels,
`no-new-privileges`, capabilities, cgroup limits, namespaces, read-only
paths), the shim and its protocol (one more optional word), the logs, the
network, exec's `process.json`, pseudo-terminal handling, and exit codes.
crun accepts the arguments Armada passes runc, with the same meanings:

| Call | Meaning in both |
| --- | --- |
| `--root DIR` | the runtime's state directory |
| `create --bundle B --pid-file F ID` | the container made from its bundle, not started; its process's stdio is the runtime's; the pid written to F before it returns |
| `start ID` | the container's process started |
| `kill --all ID SIG` | the signal (a number, or a name without SIG) to every process of the container (crun through its cgroup) |
| `delete --force ID` | killed if running, then removed; a container that does not exist is no error |
| `list -q` | one ID per line |
| `exec --process P --pid-file F [--tty] ID` | the process from `process.json` (its terminal and console size included: `--tty` changes nothing then), in the foreground; the pid written once the process runs; signals forwarded; exit code the process's (128 plus the signal for a killed one), 255 for the runtime's own failure |

Differences found in crun's source, and how they are handled:

- A terminal. With a terminal and no console socket, runc and crun each
  make a terminal of their own for the process and copy it to their
  stdout, putting their stdin (`armada-node`'s terminal) in raw mode. runc
  leaves the process's terminal translating "\n" to "\r\n"; crun clears
  that translation (`libcrun_clear_onlcr`) and its raw stdin translates
  nothing either, so a shell's lines reach the caller without "\r" and
  staircase (found in the lab). For crun, `armada-node` therefore passes
  `--console-socket DIR/console.sock` (in the exec's own directory, bound
  through the directory's descriptor so a long path works; crun connects
  through `/proc/self/fd` the same way): crun sends the master of the
  process's terminal, with its default settings and the request's size,
  over SCM_RIGHTS and closes its copy, then waits for the process in the
  foreground as before. `armada-node` copies the caller's input to that
  master (Ctrl-D at its end), its output to the caller, resizes it
  directly, and copies crun's own stdout and stderr (its errors) to the
  caller's output. The exit code, the pid file, the drains, kill, and
  abandon are unchanged; a crun that ends without sending a terminal is
  a session with no terminal output but crun's own. runc keeps its own
  terminal, unchanged (`consoleSocket` is set only for crun).
- `kill --all` on a container whose processes have all ended succeeds in
  crun (its cgroup is empty) where runc fails ("container not running").
  The agent sends `kill --all` only to end a container (SIGKILL after a
  stop's grace, or before removing it), and then waits for its exit: a
  container that ended first is the outcome it wanted. With runc, a
  container that exited between the grace and the kill made the stop fail
  with that error; with crun it stops cleanly. Nothing else changes.
- crun writes the pid file in place (one small write), runc by a rename.
  `armada-node` reads the exec's pid file until it holds a valid pid, and
  the shim reads its create's only after `create` returned, so a file not
  written yet reads as "not yet" in both.
- Error texts name the runtime that ran: `crun create exited with 1`,
  `exec: crun exec: fork/exec …`, `exec: crun exec did not start the
  process`; runc containers keep runc's texts.

## Consequences

- Each container start, probe command, and exec runs a 2 MiB C program
  instead of a 10 MiB Go one.
- The runtime pack grew by crun (about 2 MiB per architecture) while
  runc stayed, then lost runc (about 10 MiB per architecture); each
  release gains the sources asset (about 42 MB, most of it glibc's
  source), which the archives only name.
- `armadad runtime --bin-dir DIR` (development builds) needs `crun` in
  DIR.
- On the upgrade to v0.1.0-alpha.44 every node recreated its replicas
  that runc created, one at a time, and replaced HAProxy's container
  last: apps with replicas on more than one node kept serving; an app
  with one replica had a gap of about its start time. On the upgrade to
  the release without runc, a node whose move did not finish ends what
  is left on runc and recreates it at once, every such replica of the
  node together.

## Risks

- A behaviour of crun that differs from runc in a case not covered above
  shows only on real kernels: the conformance suite on a lab node
  (`supervisor::conformance`, root) runs every call on crun before a
  release.
- crun's static release build links its libraries from the nixpkgs
  revision its `flake.lock` pins; the sources asset carries each library's
  source tarball, the patches nixpkgs applies, and its nixpkgs expressions, but
  not the rest of nixpkgs (the toolchain and the build system), which
  that revision pins. Building crun in Armada's release
  workflow from the shipped tarball would make the program and its
  corresponding source one step; that is a later decision.
- Two runtimes during the transition doubled the paths that clean up
  after a shim; without runc, ending its containers relies on the cgroup
  v2 hierarchy alone (Armada requires it): a process that escaped its
  container's cgroup would not be found, which the container's own
  cgroup namespace and limits prevent.
